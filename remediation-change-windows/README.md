## Product behavior

**Ready-to-open single-file offline app:** [standalone.html](./standalone.html) (99,027 UTF-8 bytes, SHA-256 `db0c347e1a05645ca54cb85be67ea64da37904570d6bd281ac463889edd9f7df`; byte-pinned original Casework source and two SHA-256-CSP inline scripts; no network). It can be opened without another checkout. For source development, open [index.html](./index.html) in a browser from the LightUp repository checkout (keep the sibling `remediation-capacity/` folder, because this new app deliberately uses the original unmodified `casework-original-v1.js` source parser and original source digest). No server, local storage, network, external assets, backend credentials, or target contact is used.

1. Obtain the **original** private five-column CSV through separately authenticated, permitted LightUp access. Optionally obtain a **private original** Evidence Review v1/v2 JSON and an ORIGINAL `lightup.remediation_casework_draft` v1 JSON from existing Casework. The original Casework file must have 12 false authority flags, complete exact five-column original source membership and complete unique casework rows. A non-null source SHA-256 must match the canonical CSV SHA. **Original offline Casework files may legitimately contain a null source SHA:** they are admitted only with the same independent exact-client/engagement confirmation, exact complete membership and full original five-column row equality, all original `C.loadPacket` field validation, and a visible WARNING. Such hashless originals are not independently authenticated or evidence of consent. Independently confirm the same real client and *exact* engagement before joining the separate sources. A CSV/hash cannot prove an issuer.
2. The app strictly parses the original `finding_id,title,severity,retest_status,remediation` source with the unchanged original Casework parser. It binds an optional complete Evidence Review JSON to the canonical **exact source SHA-256**, rejects duplicate/unknown JSON properties, rejects true or absent authority flags, mismatched or missing review IDs, malformed human evidence fields, source drift and oversized files. Failed join removes any stale dashboard. Casework statuses, deadlines, owners and blocker notes remain read-only *human planning* fields, never independently verified remediation.
3. Propose **up to four UTC review/change windows** and allocate source findings to human discussion slots. Filter by original severity and human evidence gaps, select a proposed slot and apply one atomic *human-only* bulk assignment to the displayed cohort (up to 350 findings); undo the most recent bulk assignment in one action. Neither bulk operation overwrites any original source/retest, reviewer or human evidence reference. Use a second human filter for Casework blocked, overdue, owner-missing and proposed slots after local due dates, and view per-slot urgency/Casework blockers. **Private owner workload board:** groups exactly the local original Casework human owners, prioritizes critical/high counts and locally blocked/overdue/late/unscheduled records, and lets an operator filter the live finding queue to one owner. Original owner labels remain only in private tab data or explicitly acknowledged PRIVATE Markdown, never in identity-free calendar or aggregate CSV. View source severity/retest state, unverified local human stage, human change/deployment/rollback/retest-request reference gaps, original regressions, and high-risk/unscheduled counts. A locally filled reference is **not proof** of a verified fix or permission to execute; source `fixed` is not independently verified.
4. **Preview and continue a newer original source revision**: independently confirm that a newer originally authorized five-field CSV comes from the same exact original client and engagement; preview added, changed, exact-unchanged and absent IDs using the original Casework compareSource implementation. Only unchanged original five-field records retain unverified local human notes/slot assignments. New/changed rows are reset to empty human notes and unassigned slots; absent original IDs are counted as UNVERIFIED, NEVER fixed/closed. Preview binds the original source SHA and all current local note/window selections; stale previews HOLD without applying. No source or backend is edited. Any optional prior Casework attachment is cleared when source changes: re-import an original exact-new-source Casework packet before treating its owner, blocker or due-date content as source-bound; prior local Casework data is not silently re-labelled as original current-source evidence.
5. **Replace the original human Casework snapshot without replacing original findings**: independently obtain another originally exported Casework v1 JSON for the same real client and engagement, and preview its *complete* original-source-bound human row set against the previous Casework version. The preview strictly requires original Casework kind/schema, complete and exactly equal original five-column finding membership, source SHA matching the current CSV when present (or an explicitly flagged null source SHA in an original offline export), original `C.loadPacket` normalization, all 12 literal-false authority markers and independent same-client/engagement human confirmation. It reports which owner, case status, due date, blocker, next action, verification plan, note and update timestamp fields changed, including critical/high exposure. Before confirming the replacement, optionally export an explicitly PRIVATE old/new human field change brief; this is never an authority artifact. Both the current Casework source and local window plan are fingerprint-bound at preview time, so an input/window/evidence/source change invalidates stale adoption. **Applying** atomically updates only the private original human Casework snapshot (and human change indicators), not the original findings, evidence reviews, database, scanner or user-selected UTC slots. The current owner's workload, human queue and original Casework changed-row filter then surface the impact. The anonymized slot CSV adds only a changed-human-row count, never owners, IDs or notes. A Casework preview can be exported as a **separate confidential old-versus-new field-level Markdown** report before acceptance; after acceptance the prior private values are erased and only the changed field names are retained in the current tab. Plans bound to the old Casework SHA refuse resume against the new snapshot.
6. **Track and route a source-bound PRIVATE HUMAN follow-up per original finding**: the responsive finding table now opens a private per-finding action editor for five explicitly non-authorizing stages (**needs triage, awaiting owner, awaiting human evidence, needs discussion, discussion logged — NOT approved**), an optional human UTC reminder date and up to 600 characters of private next-action/meeting notes. An action is merely a human coordination record, not an original Casework update, consent, verified remediation or retest evidence. Logging a discussion requires a nonempty human note; bulk-marking a whole cohort as discussed rejects missing notes. Filter by human follow-up open, past due or discussion logged. ## Integrity, ownership and release fences

- This is an **isolated add-only product** under `remediation-change-windows/` on top of a frozen, already held Remediation Cockpit PR #1627 snapshot, not a change to any original source-owner path, scanner, grant, STOP, CI, deploy or QA.
- The original Casework source in `remediation-capacity/casework-original-v1.js` is unchanged. Unlike private JSON, original five-column CSV may contain a legal UTF-8 BOM; the source-owner's original CSV parser already accepts this and this app now preserves that compatibility while rejecting BOM at the **raw UTF-8 byte boundary** for private JSON, even when a decoder would strip BOM transparently. Its parser also bounds individual CSV fields and findings; the extra review JSON intake is capped at 2 MiB.
- SHA-256 is only an unsigned content correlation check. Dates, counters, human notes and client/engagement checkbox are not approvals. All generated artifacts are **human-only unverified drafts**.
- Do not merge to main, deploy, contact targets, trigger scans, grant access or treat these as verified changes without original owner review, independent security/privacy review, both original exact-head hosted and permanent registered VPS CI, issue #177/#182/#829 authorization integration, actual separately authenticated client/operator consent with revocation-at-use, and explicit **HUMAN GO**.
- No QA, regression or test suite is part of this deliverable; verification may use only a short source syntax inspection.
