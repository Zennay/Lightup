## Product behavior

**Ready-to-open single-file offline app:** [standalone.html](./standalone.html) (50,761 UTF-8 bytes, SHA-256 `13e167a53ecedca0fdb91aeb80bdf76ff69f7223816190ea0a54d1866b78b323`; byte-pinned original Casework source and two SHA-256-CSP inline scripts; no network). It can be opened without another checkout. For source development, open [index.html](./index.html) in a browser from the LightUp repository checkout (keep the sibling `remediation-capacity/` folder, because this new app deliberately uses the original unmodified `casework-original-v1.js` source parser and original source digest). No server, local storage, network, external assets, backend credentials, or target contact is used.

1. Obtain the **original** private five-column CSV through separately authenticated, permitted LightUp access. Optionally obtain a **private original** Evidence Review v1/v2 JSON from the current Evidence Review Board. Independently confirm the same real client and *exact* engagement before joining the separate sources. A CSV/hash cannot prove an issuer.
2. The app strictly parses the original `finding_id,title,severity,retest_status,remediation` source with the unchanged original Casework parser. It binds an optional complete Evidence Review JSON to the canonical **exact source SHA-256**, rejects duplicate/unknown JSON properties, rejects true or absent authority flags, mismatched or missing review IDs, malformed human evidence fields, source drift and oversized files. Failed join removes any stale dashboard.
3. Propose **up to four UTC review/change windows** and allocate source findings to human discussion slots. Filter by original severity and human evidence gaps, select a proposed slot and apply one atomic *human-only* bulk assignment to the displayed cohort (up to 350 findings); undo the most recent bulk assignment in one action. Neither bulk operation overwrites any original source/retest, reviewer or human evidence reference. View source severity/retest state, unverified local human stage, human change/deployment/rollback/retest-request reference gaps, original regressions, and high-risk/unscheduled counts. A locally filled reference is **not proof** of a verified fix or permission to execute; source `fixed` is not independently verified.
4. **Preview and continue a newer original source revision**: independently confirm that a newer originally authorized five-field CSV comes from the same exact original client and engagement; preview added, changed, exact-unchanged and absent IDs using the original Casework compareSource implementation. Only unchanged original five-field records retain unverified local human notes/slot assignments. New/changed rows are reset to empty human notes and unassigned slots; absent original IDs are counted as UNVERIFIED, NEVER fixed/closed. Preview binds the original source SHA and all current local note/window selections; stale previews HOLD without applying. No source or backend is edited.
5. **Resume PRIVATE saved planning**: re-import the prior private JSON only after exact original source SHA, unchanged complete finding membership, original severity/retest fields, matching human review digest/gaps and all 12 literal-false authority flags. Conflicting counts, overlapping windows, changed notes, missing source rows and ambiguous fields HOLD the import **before** any local window selection is changed.
6. Prevent incomplete UTC window schedules, invalid durations or overlaps from leaving as exports. Explicitly choose one of three local exports:
   - **PRIVATE source-bound JSON**, containing original finding IDs, reviewer/next step, proposed assignments, original severity/retest status, gap labels, SHA-256 and all **twelve false authority flags**. Transfer only with a separately approved confidential channel.
   - **Identity-free .ics calendar**, containing only generic tentative meeting slots, duration and a fixed non-authorizing description. No finding, target, notes, customer, reviewer or asset metadata.
   - **Aggregate-only CSV**, containing only slot, UTC time, duration, counts by critical/high and locally incomplete reference counts. No original finding data or human evidence references.

The app has no browser storage: refresh or close discards private inputs and window assignments. "Forget" removes in-memory state and selected file inputs. The portable offline browser may use the original Casework WebCrypto digest, or an in-memory source-compatible SHA-256 fallback for file:// contexts.
