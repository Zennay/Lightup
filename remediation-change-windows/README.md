## Product behavior

**Ready-to-open single-file offline app:** [standalone.html](./standalone.html) (63,701 UTF-8 bytes, SHA-256 `fd3231624afeb895d522de70fbbe00bb2d8c4c5817ae282b0ff262c96e902e9f`; byte-pinned original Casework source and two SHA-256-CSP inline scripts; no network). It can be opened without another checkout. For source development, open [index.html](./index.html) in a browser from the LightUp repository checkout (keep the sibling `remediation-capacity/` folder, because this new app deliberately uses the original unmodified `casework-original-v1.js` source parser and original source digest). No server, local storage, network, external assets, backend credentials, or target contact is used.

1. Obtain the **original** private five-column CSV through separately authenticated, permitted LightUp access. Optionally obtain a **private original** Evidence Review v1/v2 JSON and an ORIGINAL `lightup.remediation_casework_draft` v1 JSON from existing Casework. The original Casework file must have a non-null SHA-256 matching the exact source CSV, 12 false authority flags, complete five-column original source membership, and complete unique casework rows. A hashless source draft is held rather than silently linked. Independently confirm the same real client and *exact* engagement before joining the separate sources. A CSV/hash cannot prove an issuer.
2. The app strictly parses the original `finding_id,title,severity,retest_status,remediation` source with the unchanged original Casework parser. It binds an optional complete Evidence Review JSON to the canonical **exact source SHA-256**, rejects duplicate/unknown JSON properties, rejects true or absent authority flags, mismatched or missing review IDs, malformed human evidence fields, source drift and oversized files. Failed join removes any stale dashboard. Casework statuses, deadlines, owners and blocker notes remain read-only *human planning* fields, never independently verified remediation.
3. Propose **up to four UTC review/change windows** and allocate source findings to human discussion slots. Filter by original severity and human evidence gaps, select a proposed slot and apply one atomic *human-only* bulk assignment to the displayed cohort (up to 350 findings); undo the most recent bulk assignment in one action. Neither bulk operation overwrites any original source/retest, reviewer or human evidence reference. Use a second human filter for Casework blocked, overdue, owner-missing and proposed slots after local due dates, and view per-slot urgency/Casework blockers. **Private owner workload board:** groups exactly the local original Casework human owners, prioritizes critical/high counts and locally blocked/overdue/late/unscheduled records, and lets an operator filter the live finding queue to one owner. Original owner labels remain only in private tab data or explicitly acknowledged PRIVATE Markdown, never in identity-free calendar or aggregate CSV. View source severity/retest state, unverified local human stage, human change/deployment/rollback/retest-request reference gaps, original regressions, and high-risk/unscheduled counts. A locally filled reference is **not proof** of a verified fix or permission to execute; source `fixed` is not independently verified.
4. **Preview and continue a newer original source revision**: independently confirm that a newer originally authorized five-field CSV comes from the same exact original client and engagement; preview added, changed, exact-unchanged and absent IDs using the original Casework compareSource implementation. Only unchanged original five-field records retain unverified local human notes/slot assignments. New/changed rows are reset to empty human notes and unassigned slots; absent original IDs are counted as UNVERIFIED, NEVER fixed/closed. Preview binds the original source SHA and all current local note/window selections; stale previews HOLD without applying. No source or backend is edited. Any optional prior Casework attachment is cleared when source changes: re-import an original exact-new-source Casework packet before treating its owner, blocker or due-date content as source-bound; prior local Casework data is not silently re-labelled as original current-source evidence.
5. **Resume PRIVATE saved planning**: re-import the prior private JSON only after exact original source SHA, unchanged complete finding membership, original severity/retest fields, matching human review digest/gaps and all 12 literal-false authority flags. Conflicting counts, overlapping windows, changed notes, mismatched original Casework row/source SHA-256, missing source rows and ambiguous fields HOLD the import **before** any local window selection is changed.
6. Prevent incomplete UTC window schedules, invalid durations or overlaps from leaving as exports. Explicitly choose one of four local exports:
   - **PRIVATE source-bound JSON**, containing original finding IDs, reviewer/next step, proposed assignments, original severity/retest status, gap labels, SHA-256 and all **twelve false authority flags**. Transfer only with a separately approved confidential channel.
   - **Identity-free .ics calendar**, containing only generic tentative meeting slots, duration and a fixed non-authorizing description. No finding, target, notes, customer, reviewer or asset metadata.
   - **Aggregate-only CSV**, containing only slot, UTC time, duration, counts by critical/high, locally incomplete reference counts, blocked/overdue Casework counts and proposed-window-after-local-due counts. No original finding data or human evidence references.
   - **PRIVATE original Casework human follow-up Markdown**, containing exact source finding IDs, original source severity, privately declared Casework owner, local human status, blocker, next step and proposed slot. Only available with a fully source-bound original Casework v1 packet. Requires separately approved confidential recipient and sends no network requests.

The app has no browser storage: refresh or close discards private inputs and window assignments. "Forget" removes in-memory state, selected file inputs **and previously hidden DOM finding/plan text**. Selecting a replacement original CSV/Evidence/Casework file proactively invalidates the prior source-bound session, clears stale window choices and requires renewed exact-client/engagement confirmation. The portable offline browser may use the original Casework WebCrypto digest, or an in-memory source-compatible SHA-256 fallback for file:// contexts.
