## W16 — latent cross-grant effective-scope overlap (fictional-only)
A fictional cohort can contain two grants whose **selected operations are different**, yet both underlying asserted grant scopes cover the same unselected **asset+capability pair**. Previous review counted those two grants as independently coherent because it only checked duplicate requested pairs. That is not independent authority: overlapping scope contents can make their provenance ambiguous even when no duplicate operation happens to be requested.

The pure, **unwired** batch reviewer now derives each validated grant's effective scope as `assets - excluded_assets` and its exact allowed capability names, bounded by 256 each. For each newly encountered distinct grant ID (at most 32), it rejects any shared **effective asset AND allowed capability** with any other grant ID in this same fictional tenant/engagement cohort. No Cartesian-product expansion or I/O, network, resolver, grants, handlers or actual target is involved. A second asset under the exact same immutable grant snapshot remains REVIEW_ONLY. Different grants with only common assets or only common capabilities, but **no shared asset-capability combination**, remain REVIEW_ONLY. Exclusions truly remove that asset from the overlapping footprint.

**Conservative false positives are deliberate.** Real organizations might lawfully issue multiple overlapping grants; their legitimate use is to be decided by independently authenticated client/operator records and source owners, not by this synthetic consistency heuristic. The reviewer is **not** a production policy authority; all outcomes remain HOLD or REVIEW_ONLY with four literally false authority flags.
