# Offline finite NUMBER admission reference — #1143

**State:** INCUBATE M3/M7 / PLAN-LAB ONLY. Non-authorizing, opt-in, not registered with production `ToolExecutor`. No active target, network, grant, scan, deployment, or release decision.

`src/lightup/finite_number_offline_review.py` implements a strict, atomic immutable snapshot for a bounded list of named numeric arguments. Reject NaN / positive and negative infinity, bool, `IntEnum`, user-defined numeric subclasses, duplicate/invalid field names, non-tuple containers, partial batches and oversized inputs. Exact built-in finite `int` and `float` are supported, including exact finite Python integers **up to 4096 bits** without floating-point coercion. Integers above that resource budget fail closed, including when they occur at the end of a batch. The returned sorted tuple can be passed by an **explicit** synthetic call site only. The minimal receipt never includes input values or untrusted names and hardcodes all authority and deployment fields false.

`tests/test_scope_finite_number_offline_review.py` verifies real offline pre-admission with original `ToolExecutor` and disposable SQLite/evidence side effects; invalid late arguments must be refused before a caller invokes that executor. This does **not** fix original `ParamKind.NUMBER.accepts`, which currently accepts non-finite floats, nor original type-identity admission #1095. Standalone previews are not a security boundary unless the production source owner integrates mandatory admission before handlers. No claims of real authorized scan protection.

**Local CLI:** `python scripts/review_scope_finite_number_offline.py < synthetic.json` accepts at most 8192 stdin bytes and exactly a JSON envelope `{"arguments":[["count",3],["weight",0.5]]}`. It rejects duplicate JSON keys, extra envelope fields, nonfinite numeric tokens, float overflow, forged/duplicate field names, nonnumeric values and oversized batches. It outputs one fixed JSON receipt (never values or private names), returns exit **3** for local REVIEW_ONLY or **2** for HOLD and never returns exit 0. Unit tests launch the actual subprocess with real JSON bytes and verify privacy/exit codes.
