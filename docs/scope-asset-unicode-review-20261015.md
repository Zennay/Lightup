# Synthetic Unicode/alias scope metadata review — DRAFT/HOLD

This opt-in, offline **structural reviewer** addresses deceptive asset metadata. The real ScopeDefinition.allows_asset currently compares stripped/lowercased names; that is not a trust decision for Unicode confusables or URL-decorated representations. Only invented asset metadata may be passed to this tool. It does not modify ScopeDefinition, parse authorized production targets, contact DNS, query external services, inspect directories, load credential files, create permits, dispatch scans, alter production state or authenticate a client.

Usage: python scripts/review_scope_asset_unicode_20261015_offline.py --stdin-json < synthetic.json

Synthetic JSON must contain **exactly** three arrays: assets (1–32), excluded_assets (0–32), allowed_capabilities (1–32). Asset names are deliberately restricted to lowercase ASCII DNS-shaped opaque identities, 1–253 characters, labels 1–63 characters, no trailing dot and no xn-- prefix. Only canonical four-octet dotted-decimal IPv4 names are reviewed as opaque strings. Ambiguous shorthand, integer-only, leading-zero or malformed IPv4-looking names are HOLD; no lab/private range determination is performed. Valid IPv6 or IDN assets can receive HOLD: this reviewer covers only a conservative subset, never a complete target parser. Capability identifiers use lowercase ASCII letters, digits and dash/underscore/dot separators; empty capability arrays (implicitly unrestricted in current model) are denied for even this structural review.

Strict JSON/UTF-8 max 8192 bytes rejects duplicate escaped keys, nonfinite numbers, extra fields, unexpected shapes and duplicate/intersecting asset sets. Input comes from local stdin file/pipe and has a two-second EOF deadline. Input fd0 is duplicated and pinned, device/inode/type compared before each read and after EOF; regular-file input must start at offset zero, have consistent bounded length, and retain size/mtime/ctime through the full read. This is a best-effort local snapshot check, not cryptographic provenance or a defense against adversaries with full process control. REVIEW_ONLY exits 3 and contains only aggregate counts; HOLD exits 2 and has no counts. Both include six literal false flags: authorization_verified, permit_issued, dispatch_enabled, merge_approved, deploy_approved, release_approved. Nothing echoes input identifiers or approvals. Aggregate counts are not cryptographic anonymization; **never submit customer data**. Output transport is not cryptographically authenticated or fd-pinned.

Tests additionally assert that fragmented local pipe writes give byte-identical non-authorizing receipts, incomplete never-closed pipes reach a HOLD within the two-second deadline, and oversized real-CLI input is generic HOLD with no echo. These are synthetic local subprocesses; no real customer or target data is used.
