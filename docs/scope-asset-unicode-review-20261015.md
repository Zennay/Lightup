# Synthetic Unicode/alias scope metadata review — DRAFT/HOLD

Posture: INCUBATE M3/M7 · PLAN/LAB ONLY. No active scope authority is granted.

This opt-in, offline **structural reviewer** addresses deceptive asset metadata. The real ScopeDefinition.allows_asset currently compares stripped/lowercased names; that is not a trust decision for Unicode confusables or URL-decorated representations. Only invented asset metadata may be passed to this tool. It does not modify ScopeDefinition, parse authorized production targets, contact DNS, query external services, inspect directories, load credential files, create permits, dispatch scans, alter production state or authenticate a client.

Usage: python scripts/review_scope_asset_unicode_20261015_offline.py --stdin-json < synthetic.json

Synthetic JSON must contain **exactly** three arrays: assets (1–32), excluded_assets (0–32), allowed_capabilities (1–32). Asset names are deliberately restricted to lowercase ASCII DNS-shaped opaque identities, 1–253 characters, labels 1–63 characters (with exact 253/254-byte name and 63/64-label synthetic regressions), no trailing dot and no xn-- prefix. Only canonical four-octet dotted-decimal IPv4 names are reviewed as opaque strings. Ambiguous shorthand, integer-only, leading-zero, hexadecimal-octet/integer (`0x7f.0.0.1`, `0x7f000001`) and malformed IPv4-looking names are HOLD; no lab/private range determination is performed. Pure in-process `socket.inet_aton` tests, including 1,200 seeded lexical candidates with differential comparison against strict `IPv4Address`, demonstrate legacy IPv4 hexadecimal and octal aliases map to numeric addresses; the reviewer never imports a socket or performs a lookup. Valid IPv6 or IDN assets can receive HOLD: this reviewer covers only a conservative subset, never a complete target parser. Capability identifiers use lowercase ASCII letters, digits and dash/underscore/dot separators; empty capability arrays (implicitly unrestricted in current model) are denied for even this structural review.

Strict JSON/UTF-8 max 8192 bytes rejects **any** raw JSON backslash escape (including ASCII-equivalent `\\u` lookalikes and escaped separators) rather than trusting only the decoded value; duplicate escaped keys, nonfinite numbers, extra fields, unexpected shapes and duplicate/intersecting asset sets. Input comes from local stdin file/pipe and has a two-second EOF deadline. Input fd0 is duplicated and pinned, temporary O_NONBLOCK is restored even on failure, and EAGAIN after select() retries under the same strict EOF deadline; device/inode/type compared before each read and after EOF; regular-file input must start at offset zero, have consistent bounded length, retain size/mtime/ctime, **and match a second independent byte-for-byte readback under the same total two-second deadline**, rechecked again **after** EOF and both stat/content validations to reject a late result even when a read returns after readiness. This detects same-size content rewrites even if stat metadata is stale or spoofed; it does not prove cryptographic provenance against process-owner interference. This is a best-effort local snapshot check, not cryptographic provenance or a defense against adversaries with full process control. REVIEW_ONLY exits 3 and contains only aggregate counts; HOLD exits 2 and has no counts. Both direct in-memory entry points explicitly reject polymorphic dictionary keys that compare equal to canonical JSON keys. A separate final output-schema gate uses exact built-in types and refuses any direct caller-supplied APPROVED/PASS or polymorphic status, extra fields, truthy or integer-0 fake false flags, bool-as-int counters or out-of-range aggregate counts, before touching stdout. Both normal receipts include six literal false flags: authorization_verified, permit_issued, dispatch_enabled, merge_approved, deploy_approved, release_approved. Nothing echoes input identifiers or approvals. Aggregate counts are not cryptographic anonymization; **never submit customer data**. A real AF_UNIX socket supplied as stdin is rejected before reading any bytes, and a disconnected local stdout pipe exits nonzero without a traceback. Output fd1 is also pinned, required to be distinct from stdin, and checked for local FIFO or actual TTY before one <=512-byte nonblocking write; regular files, devices and sockets cannot receive even a HOLD receipt. Full output pipes return exit 2 without emitting a partial receipt, and both input/output descriptor duplicates are closed. Transport is not cryptographically authenticated; do not use a receipt as release evidence.

18 disparate real subprocess malformed JSON/UTF-8/claim/secret-lookalike cases must yield byte-for-byte the same opaque HOLD object, exit code 2, zero stderr, and no input echo. This is a content-level invariance test, not a timing-side-channel guarantee. A separate real subprocess uses an own temporary writable regular file whose size is actively truncated during the first read: the same bounded snapshot must refuse it, preserve blocking mode and emit no data. Tests include child-isolated, deterministic `fstat` identity-rebinding negative controls at fd0 preflight, midstream and EOF, plus fd1 before output; these must refuse the receipt and restore I/O modes without mutating real targets. Tests also exercise a genuine same-pipe stdin/stdout subprocess: a two-second input timeout must never create a self-fed receipt, and an exact 8192-byte synthetic JSON body is REVIEW_ONLY while 8193 bytes is HOLD. Tests additionally assert that fragmented local pipe writes give byte-identical non-authorizing receipts, incomplete never-closed pipes reach a HOLD within the two-second deadline, and oversized real-CLI input is generic HOLD with no echo. These are synthetic local subprocesses; no real customer or target data is used.
