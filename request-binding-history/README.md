# LightUp · Original Request Binding History Desk

**INCUBATE M3/M7 — PLAN/LAB ONLY — DRAFT/HOLD. This is a privacy-conscious offline review tool, not a grant, consent validator, operational security scan, revocation, or release decision.**

## User-visible capability

Open [standalone.html](standalone.html) as a local file in a browser; no server or build step. Select **2–12 original PRIVATE JSON files** produced by the independently owned, authenticated [Request Binding Readiness Desk PR #1590](https://github.com/Zennay/Lightup/pull/1590), always for the **same exact proposed engagement/scope/risk**. The original source owner's [#1570](https://github.com/Zennay/Lightup/pull/1570) request/grant predicate is not reproduced or changed here. The app does not authenticate the operator itself or touch the original database.

**Incremental workflow:** after your first 2–12 source files are accepted, use **Append new original snapshots** for 1–10 additional source JSON files, up to 12 total. A rejected append keeps the earlier original reports and all private human follow-up statuses intact. The exact proposed selection must remain unchanged; duplicate source metadata is held. The full **12 MB combined limit continues across appends**, not just within one file picker operation. Source byte SHA-256 markers for private working-draft restoration cover all current input files in their chosen order.

The product reads only the original single-selection `lightup.request_binding_preparation.v1` JSON format. Multi-scenario `lightup.request_binding_scenarios_review.v1` reports are intentionally **refused** rather than silently flattened to a misleading timeline. Select `.json` when exporting from PR #1590 (not `.html` or an anonymized `.csv`).

### Results

- Source-reported administrative candidate counts, unapproved and incompatible requests, historical stored grant counts and legacy unbound grant counts for each chosen file slot.
- **Original mismatch-reason trajectory:** a per-slot table for the exact seven source-owner reason codes (approval missing, mode, role/tenant provenance, risk, asset subset, decision chronology and residual source-owner integrity checks), with fixed human follow-up routing and explicitly non-chronological deltas. Aggregate JSON and CSV retain counts and original fixed reason codes but never individual request identities.
- **Original request-record lineage:** compare stable original 16-hex-digit pseudonymous request references `private_reference` *only in browser memory*, across adjacent selected original exports. Each pair distinguishes APPEARED/ABSENT/UNCHANGED/CHANGED (including original administrative request status, match category, requested risk, bound historical grant count and mismatch reasons). A row appearing/vanishing in copied sources is **not** proof of live issuance, consent, grant, or revocation; the source owner exports at most 500 recorded requests and source hashes are unsigned. A private pair-local row table shows original status/category side by side without showing raw request IDs. Publicly handoff-able aggregate export includes only anonymous per-pair counts: no original pseudonyms, client/asset labels or identities.
- Real original `RequestStatus` values include `submitted`, `under_review`, `approved` and `rejected`; only original `approved` rows can be administrative candidates, but even then **NEVER permission**. The importer holds contradictory source status/reason summaries, unrelated grant totals or malformed pseudonyms rather than inventing an approval.
- Revision-change and count deltas between adjacent files selected by the human. *A different stored-source hash means at least one originally exported source record differed, not which record, which actor changed it, or whether a grant was revoked.* Same unsigned digest is not a live-state guarantee either. Files may be deliberately reordered; selection order is **not verified chronology**.
- **Per-request casework:** each private pseudonymous original record can have a locally chosen human discussion stage and a bounded 180-character PRIVATE note. Navigable pages show 60 cases at a time. When an appended source changes original fields for a previously discussed case, the local stage returns to *Independent security/source review*; its private note is preserved for a human to reconcile. None of these stages modifies the original LightUp database or represents approval. The anonymous CSV is a single consistent row schema including source, reason, pair-difference and human discussion aggregate totals; it never exports individual record pseudonyms or private notes.
- Built-in general human follow-up checklist. Export aggregate JSON/CSV without source fingerprints, file names, client/asset/request identities, or private notes. Printing shows a **separate aggregate-only print document**; the on-screen original source table, private source hashes, original request fields and per-record private notes are hidden from paper output.
- Optional PRIVATE stage-resume JSON **v2**: uses WebCrypto SHA-256 of the full original raw JSON **byte sequence** for every selected file in its original order. It can preserve both general discussion checkmarks and case-level stages/PRIVATE notes, using positional binding to original source bytes instead of exporting record pseudonyms. Earlier v1 checklist-only private drafts can still be opened. A bounded v2 draft is limited to 2 MB, and restoration rejects changed source files/order or malformed stages/notes atomically. Protect this private file: it contains your own sensitive discussion notes. This unsigned hash is local integrity, not an authenticated signature or consent.

### Strict input boundaries

Import is **atomic**, bounded to 12 files of <=2,000,000 bytes each and <=12,000,000 bytes total. The parser rejects duplicate JSON keys (including escaped equivalents), invalid JSON/escaping, nonfinite JSON numbers, deep/complex input and trailing data. Original source format, original PR-1570 owner label, original five literal `false` authority flags, exact 64-digit unsigned source/selection digests, canonical status/disposition, candidate counters, unique pseudonymous row labels, exactly seven original source-owner reason codes, original reason totals and summary consistency must agree. A failed import leaves the prior accepted workspace and human stages intact. An exact SHA-256-pinned inline Content Security Policy rejects remote scripts, styles, network connections, frames, images and other embedded content. Invalid JSON string/escape parsing failures are reported only as generic HOLD reasons without showing private source fragments. No network requests, browser persistence, cookies, analytics, external CSS/scripts, credential handling, target access or mutation.

Scope-selection equality compares the **unsigned original selection digest claimed by each copied export**. This app cannot recompute that digest from anonymous imported data because original tenant/engagement and exact proposed assets may have been deliberately withheld. It is not verified tenant identity, current operator authentication or permission. Original operator reports may be stale, tampered with or generated from divergent feature branches. A comparison is always informational only.
