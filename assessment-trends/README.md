## Accepted source schema

Each file is the already-produced JSON object from assessment_runtime_compare_cohort_cli_1513.py:

- Exact top-level keys: status, regressed_scenarios, comparisons, authorized, consent_verified, dispatch_allowed, release_allowed.
- Each comparisons[] item contains exact keys scenario_id, status, regressions, changes.
- Each changes[] item contains exact keys name, baseline, candidate, delta, regression, in the comparator's canonical 15-metric order.
- status is HOLD or REVIEW_ONLY; the status and regression arrays must agree with the imported source metric flags. All four authority flags must be literal false.
- Counters, scores, costs, finite values and candidate minus baseline = delta are bounded and reconciled. Scope/policy and findings metrics use the comparator's existing directionality; operations metrics are informational.

The input is treated as untrusted and unauthenticated. Matching scenario IDs or baseline numbers is not proof that source files, measurement claims, chronology or lab environments are authentic.

## Spreadsheet-safe CSV serialization

Every CSV export uses one shared serializer. It quotes fields, doubles embedded quotes,
normalizes CR/LF in text cells, and prefixes string values with an apostrophe when they
begin with a spreadsheet formula trigger (`=`, `+`, `-` or `@`), including when
leading whitespace comes first. Numeric JavaScript values remain numeric cells, so
negative metric values are not converted into text. CSV output is still untrusted review
data and must not be treated as an authenticated source or release decision.

## Per-metric flag-state transition matrix

The transition matrix compares every metric across adjacent pairs by default and can switch to **all distinct manual-slot pairs** (up to 66 pairs for 12 snapshots). Each anonymous scenario contributes exactly once to one of four categories per pair: clear in both slots, flagged in both, clear → flagged, or flagged → clear. It also reports previous/current flagged counts, changed-scenario count and net flag-count change. The selected scope and pair count are included in JSON/CSV/printable handoffs. The existing static review-group filter is shared with the distribution views; a separate transition filter narrows the displayed/exported rows. All slot order remains operator-selected and unauthenticated.

Export the filtered matrix as anonymous CSV, JSON or a script-free printable HTML brief. The output contains fixed metric/group labels, manual slot numbers, aggregate counts and literal false authorization/consent/dispatch/release fields only. It excludes original scenario IDs, filenames, source hashes and HUMAN notes. A flag missing from a later selected slot is not proof of a fix, and the manually selected order is not authenticated chronology.


The local-only drilldown can filter the scenarios behind one selected metric and **any two distinct manual slots**, including non-adjacent pairs, by flag state. The aggregate transition matrix has an adjacent-only default and can be switched to all distinct pairs. The pairwise handoff v2 records both manual slot numbers and whether the selected pair is adjacent, so recipients do not have to infer pair semantics. “Open trajectory” switches the existing anonymous scenario view and HUMAN commentary editor to that scenario; CSV/JSON/script-free printable HTML exports include only filtered anonymous ordinals and source-reported values, never original IDs, filenames, hashes or HUMAN notes. This is a tab-memory-only display-order comparison with no network or authorization behavior; a flag missing in the later-selected slot is not a verified fix.


The transition drilldown also exports only its currently filtered anonymous cases as CSV, JSON or script-free printable HTML. These handoffs contain a local anonymous scenario ordinal (never the original scenario ID), selected metric/group, manual slot pair, flag state, reported values and literal false authorization/verification fields. They do not include original filenames, source hashes or HUMAN notes and do not assert that a missing flag is a verified fix.


## Local HUMAN commentary undo and redo

Commentary saved or cleared in the offline browser editor can be undone and redone up to 20 steps in tab memory. Undo/Redo controls display the available counts; Ctrl/Cmd+Z, Ctrl/Cmd+Y and Ctrl/Cmd+Shift+Z also work outside editable fields. Snapshots contain only private saved notes and drafts and are bound to the exact active in-memory source cohort and its source-byte fingerprints. Undo/redo never changes original assessment metrics, source status, HUMAN stage marks, scan authority or consent. Importing a new source batch, loading the fictional demo, explicitly forgetting data, importing an encrypted note packet or restoring a private session clears the history. No browser storage, persistence or network action is used. A local unsaved draft triggers confirmation before a history restore.


### Clear notes without losing source comparisons

**Clear all HUMAN notes and drafts** clears only private saved commentary and unsaved drafts after explicit confirmation. Original cohort snapshots, metric values, status and HUMAN stage marks remain unchanged. Clearing is one reversible edit in the bounded 20-step local note history until history is discarded, while **Forget** clears the source data and both undo/redo stacks. Nothing is persisted or sent over the network.
