## Open and operate

Open standalone.html locally in a browser (no server required), or load index.html with the adjacent local style.css and app.js. After importing or opening the fictional demo, use the sticky, keyboard-accessible horizontal section navigation (sources, version comparisons, human case queue, discussion agenda and handoffs). It is automatically omitted from printed and exported briefs. The standalone file is built reproducibly with python3 assessment-trends/build_standalone.py using stdlib and a restrictive content-security policy with SHA-256-pinned inline CSS and JS. No HTTP clients, external scripts/fonts/images, browser storage, remote endpoints, filesystem scans or background worker.

1. To explore without original data, select **Explore fictional demo**. It creates five deterministic made-up report revisions and eight invented lab cases entirely in local memory; nothing is fetched or scanned. The visible DEMO banner stays present in print and exports contain the `FICTIONAL_DEMO_ONLY` source marker. Private source-bound draft save/restore is unavailable in demonstration mode.
2. From existing, separately obtained original [assessment-runtime #1513](https://github.com/Zennay/Lightup/pull/1515) exports, choose **3–12 original cohort comparator CLI JSON reports**, each at most **262,144 bytes**, in the display order you want. The selection order is not proven run chronology.
3. **Append later:** after initial import, use **Append one original lab report** to add one existing, distinct canonical output, until 12 reports are loaded. A changed baseline, duplicate candidate metric snapshot, malformed original or oversized file causes atomic HOLD without replacing earlier reports or human discussion work. Source hashes and labels are preserved, the new source occupies the end of the user-selected unverified order, and old private drafts deliberately cease to bind to the new source set. Demo mode cannot be mixed with real reports. Each original report must have status, regressed_scenarios, comparisons and the four literal-false flags authorized, consent_verified, dispatch_allowed, release_allowed. Comparison records must have the original scenario_id, status, regressions, and all fifteen complete canonical metric changes. This tool rejects partial HOLD packets, single-case output, foreign schemas and changed baseline sets.
3. **Reorder reports after importing.** File-picker order cannot be trusted to reflect chronology. The workspace has explicit earlier/later controls which recalculate all trends and exports without new network calls. This is an unverified user-selected order.
4. Inspect the **local-only source manifest**: assign optional 40-character private aliases to visually distinguish imported reports when reordering. Only short SHA-256 prefixes (if browser WebCrypto supports them) and input-byte counts are shown; original filenames are never copied. These local aliases/fingerprints are deliberately absent from all aggregate exports and printouts.
5. All revisions must carry **exactly the same scenario IDs** and the same original baseline value for each metric of each scenario. Different baselines are not silently reconciled. A mismatched or malformed batch replaces nothing and shows a generic HOLD message.
6. Start with the **metric topic cards**: scope/policy flags, detector coverage, evidence/scoring or operational information. Source-reported last-candidate baseline regressions, adjacent deteriorations and neutral changes are counted without introducing a security/risk score. Select a topic to filter the 15-metric landscape, or return to all metrics. Select **any two different existing candidate revisions**, not only adjacent ones. The comparison shows all 15 category aggregate changes, plus a private local per-scenario drilldown that can open the anonymous case inspector; its dedicated rectangular CSV handoff and aggregate JSON v8 contain only numeric aggregates and source positions, never scenario IDs. Selected position does not certify chronology. Use the **four-dimension descriptive lab tradeoff explorer** to compare adverse metric observations, assessed coverage, runtime and compute cost. Toggle dimensions and see which imported candidate positions are numerically non-dominated under only those selected lab measures; this is not a recommendation or release/safety decision. Explore regressed-scenario counts for every metric and revision, persistent/newly emerged/recovered flags, and original baseline/candidate/delta aggregates. Independently inspect **adjacent candidate-vs-candidate changes** across all successive source positions: a candidate may deteriorate from the prior revision even while still not worse than the original baseline. Stepwise adverse observations feed the human review register; informational counters/runtime/cost never create an adverse judgement. Performance/cost are informational rather than adverse. Enter optional discussion notes locally; these are deliberately never included in exports.
7. **Human discussion agenda**: from the case inspector, choose a proposed generic reviewer function and an optional calendar date for a conversation, never for a scan. Filter the local agenda by proposed date, still-pending discussion or critical source category, and export a clearly PRIVATE agenda CSV containing only source-case ordinals, allowed discussion enums and dates. The aggregate JSON and script-free client brief contain only counts by generic function and overall discussion progress, never exact dates, case IDs, aliases, credentials or notes. Inspect the anonymized per-case churn grid (source IDs remain internal, never exported). The **confirmed bulk discussion workflow** applies optional generic route, local human discussion stage and/or proposed discussion date to the currently visible filtered anonymous cases, with one confirmation and in-memory Undo. It cannot assign real work or book any scan; unchanged values are preserved. The **priority-ordered human triage queue** filters critical/high, persistent/newly emerged/recovered, sequential worsening and locally pending case discussions. Reviewers can jump to the next visible adverse case without task assignment. Priority is only from untrusted lab regression categories and does not imply remediation. The new **case inspector** opens an anonymous scenario across all original source revisions, showing every metric’s original baseline and candidate value with flagged adverse cells. Cases also support locally editable human discussion stages without identities; aggregate stage counts appear in the review-only JSON. A source-driven human review register now prioritizes critical scope/policy, detection and other adverse metrics, shows persistent/emerging/recovered signal and permits a private discussion-stage selection without any actual assignment or verified remediation.
8. **Resume later (optional)**: Explicitly download a separate private draft containing only source-file SHA-256 byte fingerprints, metric-level discussion stages and per-case ordinal discussion stages. Reopen the exact original 3–12 files, manually arrange the same display order and import that private draft. Wrong or changed bytes, order, extra fields, duplicate JSON keys, true authority claims or unexpected stages and repeated/out-of-range case ordinals are rejected atomically. The private source-bound draft is now v5: it saves role and date alongside local case stage, plus the reviewer-selected metric topic (scope, findings, evidence or operations), metric, any-pair comparison, latest adjacent transition, current case, filters, four descriptive tradeoff checkboxes and local-only source aliases. Exact v1 metric-only, v2 metric-and-case, v3 human-agenda and v4 full-view drafts remain restorable against identical original source bytes; restoration rejects changed/invalid dates, role enums, out-of-range revision/case selections, non-enumerated filters, malformed aliases or nonboolean dimension selections atomically. Public aggregate exports still exclude all private aliases, case ordinals and exact discussion dates. A hash is not a signature, evidence or permission. If browser WebCrypto is unavailable, draft save/restore is disabled, while the main trend analysis still works.
9. Export explicit aggregate-only CSV/JSON, a separate **script-free private HTML discussion brief**, or print. Reports contain numeric aggregates, fixed metric names and relative positions only. They contain **no scenario names/IDs, raw original files, source filenames, network target metadata, customer identifiers, credentials, notes, SHA fingerprints or inferred authorization**. A report with no counted regressions still remains REVIEW_ONLY, never PASS/GO.

## Threat and provenance boundaries

- JSON is read with a bounded recursive parser which rejects duplicate keys (including escaped-key aliases), nonfinite values, unexpected fields, missing or duplicate scenarios, invalid metric types/ranges/deltas, inconsistent regression labels, wrong global verdict, reordered/missing scenario membership, changed baseline or any true/extra security claims. Import is **atomic**.
- Matching scenario IDs, stable baselines or improved scores do **not authenticate** original records, confirm that source files came from the LightUp CLI, prove common lab ground truth, imply remediation, verify consent, authorize a retest or establish any release decision.
- The reviewer's chosen sequence is not authenticated temporal data. We do not infer actual run timestamps, model provenance, real asset identities or causality. Source reports are *untrusted*, and no client secrets should be included.
- Up to 64 canonical source scenarios; 15 metric names; 3–12 reports. The browser runs locally without network or browser persistence. Downloaded reports require normal local privacy handling. The original input JSON remains in browser memory until **Forget** or page close.
- This workspace owns only new assessment-trends/ paths. Actively owned comparator PR #1515, reviewdesk PR #1576, scope-authorization, production app, original CI, scanners and runners remain untouched.
