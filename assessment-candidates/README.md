# LightUp · Offline Lab Candidate Matrix

**Stage: INCUBATE M3/M7 · PLAN/LAB ONLY · DRAFT/HOLD.** [Product issue #1591](https://github.com/Zennay/Lightup/issues/1591). This is a private offline human discussion instrument, **not an assessment scanner, production release recommendation, client consent verifier, safety verdict or grant service**. The four output fields `authorized`, `consent_verified`, `dispatch_allowed` and `release_allowed` are always false.

## Open immediately

Download [standalone.html](standalone.html) and open it in a modern local browser. There are no external dependencies, HTTP calls, install steps, accounts, browser storage, cookies, persistence, registered service workers, target interaction, execution commands or backend. `index.html` also works alongside `app.js` and `style.css`. The self-contained release is rebuilt by `python3 assessment-candidates/build_standalone.py` using Python's standard library, with a restrictive CSP hashing the original inline script and CSS.

Click **Explore fictional demo** to view four made-up candidate outputs for four invented lab cases. They are unmistakably labeled fictional in the screen and exported JSON, and no assessment is performed.

## Compare real *pre-existing* offline lab summaries

1. In the existing separate assessment-runtime comparator [draft PR #1515](https://github.com/Zennay/Lightup/pull/1515), use its own opt-in cohort CLI to create already-finished offline output. This matrix **never invokes the CLI**, imports source data only, and does not validate original source authenticity.
2. In this independent workspace, select **2–12** locally stored canonical cohort comparison JSON documents, up to 262,144 bytes each. They must share exactly the same 1–64 canonical scenario IDs and all fifteen original baseline values for each scenario; candidate values must be distinct. Original output has exactly: `status`, `regressed_scenarios`, `comparisons`, and all four literal-false authority fields. Each comparison has exactly `scenario_id`, `status`, `regressions`, `changes`. Each change has exactly `name`, `baseline`, `candidate`, `delta`, `regression`. Reports carrying incomplete HOLD records or unknown authority fields are rejected. All files are parsed and checked as one transaction before any existing workspace is replaced.
3. **Append one new candidate**: after importing 2–11 original reports, use **Append one matching candidate** to add a separately created #1515 canonical report without reselecting earlier files. The import checks the original baseline for all fifteen metrics and all scenario identities against the existing set, rejects repeated candidate snapshots and leaves the previously accepted workspace intact on invalid input. Accepted append preserves current review thresholds, Pareto choices and case focus; adding the source necessarily invalidates all previously exported private byte-bound preference drafts until a new private draft is saved. Appending is disabled for fictional demo and after reaching twelve source files.
4. Explore source-report scorecards. Inspect critical scope/policy figures **separately** from performance/cost. The original source can report HOLD due to one or more metric regressions; **neither HOLD nor REVIEW_ONLY is an execution authority**. Candidate order is for display only, not authenticated run chronology.
5. Inspect the full **15-metric cross-candidate aggregate matrix**, preserving the exact original shared baseline for each source metric and reporting independently the adverse case count per candidate. Select any two distinct candidates to view explicit source-reported numerical changes (second minus first). This is not a newly conducted assessment or original source classification.
6. Configure six **hypothetical human discussion thresholds**: max scope and policy violations, minimum mean evidence-quality and assessed-coverage floors, optional max aggregate runtime and cost. Thresholds only classify whether an analyst should discuss results; clearing them does not mean safe or releasable. Invalid inputs make the threshold/tradeoff/export view HOLD, never export stale values.
7. Select any subset of four illustrative Pareto comparison dimensions (quality, coverage, runtime, cost). Undominated candidates are *only numerically undominated under these user-selected, untrusted lab metrics*. Safety/adverse source flags are never traded away or incorporated into permission.
8. Select **Lab case 01…64** and any of the original **15 metrics** to inspect baseline, candidate value, delta and reported regression across the same anonymized case. Original case IDs are not displayed or exported.
9. Export aggregate-only CSV or JSON, download a self-contained **script-free human discussion HTML brief**, or print a private discussion view. Demo provenance is present in every export (explicit `fictional_demo_only` CSV/JSON metadata and `FICTIONAL DEMONSTRATION` HTML heading); the exported HTML has a strict no-script, no-network CSP and describes each candidate's source flags and human discussion triggers without leaking source case details. Exports use numbered candidate slots, bounded aggregate numerical metrics, fixed original metric names, optional thresholds, false authority flags and the demo provenance marker (JSON). The aggregate JSON v3 also includes only aggregate counts by human discussion stage and generic reviewer group; aggregate CSV includes anonymized totals of local discussion progress, not identities. **No source filenames, original scenario IDs/names, URLs, hosts, client identities, credentials, raw original input bytes, free-text notes or hashes are exported.** Save exported local files in a private, appropriately protected location.

**Direct pair crossover:** Alongside total numeric deltas, select any two original candidates to see, for every one of the 15 metrics, how many of the exact same original lab cases are flagged adverse in only the first candidate, only the second, in both, or in neither. Also see anonymous case counts with any first-only/second-only flag. This is *not* authenticated chronology and an absent original flag does **not** prove remediation, coverage, consent, release, or safety. Aggregate-only crossover is included in the public JSON v3 and script-free human briefing; source case IDs and target metadata remain omitted.

**Human discussion queue:** The app now computes an anonymous cross-candidate case register from all the imported original lab findings. It shows the number of original source-adverse metrics for each case, can filter by one candidate and four metric topics, and keeps local discussion stage and generic proposed review group per anonymous case. You can select a case in the queue, inspect the same case's original metric values in the case inspector, mark whether a *conversation* is needed, being discussed or documented, or clear local discussion selections. None of these local flags updates the original LightUp findings, assigns a person, books a review/scan, creates any workflow, or demonstrates that an underlying issue is resolved. The queue uses ordinal display labels and never exposes source IDs in public exports.

**Operational metric correction:** The operations topic uses an explicit count of changed source-reported runtime, compute-cost and other operations metrics, which are *informational only*, not regression flags. The general human queue prioritizes original scope/policy-adverse cases before other source-reported adversities; this is a descriptive human attention order, not a numeric risk score, scope permission or authorization verdict.

**Human bulk discussion proposals:** Filter the cross-candidate queue to one candidate, lab metric family, existing discussion stage and whether to include cases without any original source adverse metric. The display is sorted by reported adverse metric count and shows numbered clickable local case labels. An explicit confirmation updates the generic reviewer group and/or discussion stage for **only the currently visible filtered cases**; unselected fields are preserved. One-step local Undo reverses the last batch. Any subsequent individual edit, source replacement or source append clears Undo so it cannot silently discard newer discussion choices. All work remains in memory; no real operator/person/team assignments, target interaction, consent or action approval occur.

**PRIVATE explicit save/resume:** After real canonical files have been loaded and browser WebCrypto can compute SHA-256 hashes of their **exact original bytes**, use **Save PRIVATE preferences** to download an unsigned, separately handled JSON draft. It contains only original source SHA-256 fingerprints (never source filenames, case IDs or raw content), the six local review thresholds, four chosen Pareto dimensions, the candidate pair, the anonymized case ordinal and currently selected metric. Re-import the exact same 2–12 original source files in the exact same selected order, then select the private draft to restore that review view. Any changed/reordered source bytes, wrong schema, duplicate keys, unsafe numerics, extra fields, mismatched fingerprints or true authority fields are rejected before the UI is changed; previous review work remains intact. The **v2** private draft additionally stores each local anonymous case's generic proposed reviewer group and human discussion stage as **numbered ordinals only**. The v1 settings-only draft remains compatible and restores an empty default discussion queue. Source-byte hashes are checked before any settings or discussion state are changed. No free-text notes, people, raw original case IDs or targets are persisted. The private draft is not a public report or consent/provenance evidence. This optional feature is disabled in fictional demo and on browsers without WebCrypto. No preferences are saved to browser storage.

**Reset:** **Forget all** immediately clears source records from the app's in-memory state. Closing the browser clears its page instance; there is no background state, persistence or autosave. Failed import never replaces previously imported sources.

## Fail-closed semantics

- Strict recursive JSON reader rejects duplicate keys even through JSON unicode escapes, malformed/overlong nesting, excessive entries, nonfinite numbers and invalid UTF-8.
- Enforces exact object-key sets, literal-false authority flags, max 12 source files, one to 64 scenarios per report, safe nonnegative integer count metrics, bounded float scoring/cost/time, delta arithmetic coherence, regression direction/flag coherence, whole-report HOLD status coherence and exact cross-report shared baseline/scenario membership.
- Rejects repeated candidate numeric snapshots, zero-length or oversized files, missing/incompatible metrics or inconsistent case identity, while leaving the previous in-memory workspace unchanged.
- Text originating in lab inputs is never interpolated as HTML, exported or presented as real authority; user-facing cases use local ordinal numbers.
- No reading disk other than explicitly picked files, and no DNS or HTTP APIs. CSP `connect-src 'none'`, `default-src 'none'` and SHA-256 hashes restrict the standalone artifact.
- Stage remains **DRAFT/HOLD**. Original source-owner #177/#182/#829 repairs, independently authenticated client and operator consent plus revocation-at-action, complete existing exact-HEAD hosted and permanently named registered VPS CI, independent privacy/security review and explicit HUMAN GO remain unfulfilled release gates. **Do not merge or deploy to production.**
