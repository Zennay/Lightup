# LightUp Scope Intake Matrix — HUMAN preparation only

A complete, private, networkless operator workroom for proposing assessment boundaries and comparing revisions before the original authenticated LightUp scope/consent workflow. The local UI is in **index.html** and **app.js**.

## Open

Save both files into the same local folder and open index.html in a modern desktop browser. The page loads no external resources and does not call endpoints, create grants, scan, evaluate findings, open a provider, or store records in localStorage/cookies/IndexedDB. The HTML uses a strict no-network CSP and a local script. Prefer standalone.html, a self-contained, one-file offline app with SHA-256 CSP-pinned production JavaScript. Rebuild after source changes with python3 scope-intake-matrix/build_standalone.py. No server is needed. Do not enter secrets, API keys, customer login details or active-target credentials.

## Product flow

1. Name the internal draft, enter a self-declared, unverified client label and human reviewer alias, requested local start/end times, proposed descriptive ceiling and human review questions.
2. Add 1–32 literal host / IPv4 / narrow canonical CIDR entries. You can also paste 1–32 exact lines in the bulk panel, prefixing ! to mark exclusions; all entries must pass canonical shape/duplicate/32-row admission before any row is inserted. Trailing newlines are accepted, but blank middle lines fail atomically. Mark each as a proposed inclusion or explicit exclusion. For included entries choose a proposed passive inventory, HTTP, TLS, combined passive inventory/HTTP/TLS, or isolated-lab review capability. One literal asset can now carry multiple explicitly planned passive capabilities without duplicate conflicting target rows. Mark ownership evidence as unverified, claimed (unverified), or documents requested. Track draft, needs-client-review, or blocked with a private question per row.
3. Human triage bulk actions apply to the **currently filtered visible proposals only**. First preview each literal before→after status or unverified ownership label; confirm atomically. The last 20 bulk label actions may be locally undone until any other draft mutation. Labels never authenticate clients or ownership. Filters and previews remain local; editing a status immediately refreshes visible rows.
4. Prefer **Save encrypted PRIVATE workroom** to produce one local .luie package. A strong user-chosen password (minimum 14 UTF-8 bytes), fresh 16-byte random salt, random 12-byte AES-GCM nonce, PBKDF2-HMAC-SHA256 (600,000 rounds), AES-256-GCM authenticated encryption with purpose-bound associated data, strict canonical authenticated source and 100 KiB envelope limit protect local contents from casual plaintext disclosure. Opening and comparing encrypted older drafts reuses the same original strict source schema after local decryption; failed decrypt never replaces current data. Passwords cannot be recovered and JavaScript strings cannot be reliably wiped. This protects confidentiality/integrity **only against someone lacking the password**, not client/operator identity or authorization. Use a browser that supports secure local file contexts and WebCrypto; no automatic fallback to plaintext.
5. **Re-encrypt PRIVATE file for new recipient** reads an existing source-bound .luie through its old password, admits the complete original source, and (only after explicit human acknowledgement) outputs a new separately password-protected .luie with fresh independent salt and nonce **without replacing the active workspace** and without an intermediate plaintext download. Encryption does not prove who the recipient is or whether sharing is permitted; agree on that out of band.
6. Inspect live completeness warnings. Export a PRIVATE plain JSON proposal only once schema, uniqueness, date, string and exclusion-capability checks pass. Export requires a separate local privacy acknowledgement. All five authority booleans are literally false.
7. Legacy unencrypted JSON is available only under the Advanced controls for compatibility. Later open the exact app-generated private JSON locally. The imported file must be <=64 KiB, strictly canonical JSON, exact schema and key order with no duplicate keys, all required fields and bounded nested records. Invalid UTF-8 source bytes are decoded with a fatal decoder and rejected rather than being silently replaced. Malformed or altered imports fail atomically without replacing the in-memory draft.
8. Compare the current draft against a separately opened older valid app-generated draft: explicit added, removed and field-changed literal proposals. The on-screen comparison is cleared immediately when the proposed scope is subsequently edited, preventing stale diffs. The independent HUMAN impact panel conservatively highlights literal new inclusions, removed exclusions, extra requested capabilities, increased descriptive risk or wider requested local windows as **potential widening, HUMAN HOLD**. It separately distinguishes proposed restrictions from any real revocation, plus changed client labels requiring new identity review. A scriptless PRIVATE HTML change brief can be saved locally; it is unencrypted and needs human disclosure approval. These are not approved scope changes or proved revocations.
9. A built-in HUMAN follow-up agenda derives a private task list from requested capabilities, ownership proof gaps, exclusions, blockers, questions and risk. An additional SCRIPTLESS PRIVATE HTML download is source-escaped, CSP-protected and capped at 64 KiB; human approval remains external.
10. Optionally export a separate aggregate-only counts file (with a human acknowledgement for possible small-cohort disclosure) or print a PRIVATE human brief. The aggregate omits client/asset labels and free text.
11. Clear the page's in-memory draft explicitly. Reloading also discards unsaved data. The page never automatically saves or sends it.

## Deterministic proposed IPv4 exception workroom

The browser now includes a separate visual, continuously recalculated **local IPv4/CIDR boundaries and exceptions** desk. This is an actual end-user review tool, not a test utility. It computes, purely from the human-entered canonical IPv4 literals and /24–/32 networks, every pair of numeric intersecting ranges (bounded by 32 proposals). Exact CIDR/address intersections and subset relationships are numeric; nothing is resolved over the network.

- Distinguishes **proposed included vs explicit excluded** overlapping pairs (human exception review), overlapping proposed inclusions (potential duplicated capability/ownership preparation), and overlapping exclusions. Such findings do NOT automatically invalidate intentionally narrower exceptions and never create a grant or permission.
- Adds a **single explicitly confirmed HUMAN work queue action** for affected included rows from overlapping pairs: all impacted proposed inclusions are marked `needs-client-review` in the private draft. It preserves existing exclusions and capability choices, does not create permission, and can be reversed using the existing local HUMAN bulk undo. This is a practical review-preparation shortcut, not a new authorization gate.
- Shows static IPv4 address-family notes (RFC1918, loopback, link-local, RFC 5737 documentation, CGNAT, benchmark, multicast, reserved, etc). These are literal numeric classifications; they do not prove actual network routing, ownership or internet reachability. DNS hostnames are **never** resolved and never inferred to be covered merely by suffix.
- Adds relevant inclusion/exclusion and overlapping-inclusion HUMAN follow-up questions to the live task agenda. The operator can download a **PRIVATE UNENCRYPTED, scriptless** HTML boundary exception brief only after a separate human disclosure warning. Its private labels are escaped and its CSP prevents external content.
- Optional aggregate-only source-free JSON now includes **counts of numeric overlap, inclusion/exclusion exception pairs, repeated inclusions/exclusions and static special-use family rows**. This can help the human review coordinator triage without leaking literal target strings or client labels; small groups remain sensitive and need the existing separate disclosure acknowledgement.
- A zero-overlap display means only that the current *valid literal IPv4 rows* contain no numeric intersections. It never means the actual domain policy is correct, that all DNS records are safe, or that the intended authority is available. Malformed/unfinished rows are excluded from coverage calculations and still surface in the completeness validator.
- A separately bounded **proposed target membership inspector** takes up to 16 exact IPv4 host or lowercase DNS literals, performs IPv4-within-subnet arithmetic or an exact DNS string match against the human draft, and presents separate proposed inclusions, explicit exclusions and an **always NOT AUTHORIZED** human status. It does not resolve DNS, prove host ownership, infer IPv6 or authorize a target. A scriptless private HTML membership report is available only after a disclosure warning. The inspector refuses duplicates, noncanonical targets and partial imports atomically; editing the draft or target text clears stale results. Even a matching included target is NEVER executable from this tool.
- This workroom does **not** implement a real CIDR exclusion policy, authorization, DNS lookup, target interaction, vulnerability finding or scanner. The original domain-owned authenticated membership, client/operator consent and at-action revocation controls remain mandatory.

## Trust boundary

**INCUBATE M3/M7 · PLAN/LAB ONLY · DRAFT/HOLD.** The UI is deliberately not connected to any source-owned domain authorization logic, request registry, persisted grants, approval workflow, action-time revocation, execution permit, worker or scanner. A checked-off input is self-declared content, not independent customer or operator authentication, ownership proof, security review, revocation, evidence, risk approval or HUMAN GO.

- PREPARATION_ONLY is never AUTHORIZED or PASS.
- Added entries are not granted; excluded/removed entries are not evidence of actual revocation.
- A locally complete plan may still be entirely unauthorized or outside approved risk.
- Local time inputs are planning hints, not authenticated timestamps.
- Receipts, plain JSON and printed PRIVATE reports remain unsigned and unencrypted. The optional local encrypted PRIVATE workroom uses browser WebCrypto and a password, but **does not prove origin authenticity or consent**. Human-validated separate disclosure and destination authorization are still required.
- No broad/wildcard asset input is accepted: explicit lowercase DNS names, canonical IPv4, /24–/32 canonical IPv4 networks only, with no path/port/scheme.
- An alleged ownership claim remains unverified even when a human marks it as claimed.

Release into main, production deployment or action against real customer targets remain on HOLD. Existing exact-head GitHub-hosted and permanently registered named VPS CI, original source-owner acceptance, independent security/privacy/browser review, original #177/#182/#829, separately authenticated current client/operator consent and action-time revocation, and explicit HUMAN GO remain necessary. No part of this draft package alters those gates.

## Product integrity

The import function deliberately accepts only the exact pretty-printed UTF-8 JSON representation produced by this app. This excludes duplicate JSON keys and other alternate spellings without parsing ambiguous JSON into trusted state. Text values reject invisible format/control categories; every downloaded artifact uses a bounded, explicit operator click. The offline interface uses DOM text/value assignment for entered fields; it never injects those fields into HTML markup.

Only production JS parse / artifact construction and direct read-only inspection are intended in this implementation; no QA, regression or test suites are added or executed under the 17 October 2026 instruction.
