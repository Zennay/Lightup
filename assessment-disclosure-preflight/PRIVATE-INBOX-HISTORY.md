# LightUp PRIVATE source-free HUMAN revision history

**INCUBATE M3/M7 · PLAN/LAB ONLY · REVIEW_ONLY/HOLD.** This is a
local, original-source-free private coordination aid. It never executes
an assessment, contacts clients, scans assets, authenticates reviewers,
records a grant, resolves a vulnerability or authorizes a release.

## What you can do

Compare **2–8 complete original HUMAN action worksheets** saved at
different manually selected moments against **the same exact original
source-free inbox board**. The history includes all original 1–12 slot
memberships, even unchanged or currently unreviewed slots.

The read-only admission rejects changed board bytes, unknown/duplicate
CSV columns, missing/reordered slots, inconsistent SHA-256 board binding,
noncanonical stages or roles, unsafe notes, duplicate complete revisions,
unexpected output inventory, and local file ownership/mode drift.

Results are private and source-free, **not anonymous**:

- Scriptless `PRIVATE-inbox-HUMAN-history.html`: per-round stage summary,
  per-slot stage/role progression and changed-only adjacent transitions.
- `PRIVATE-inbox-HUMAN-history.csv`: complete slot-by-round statuses, proposed
  roles, original HOLD counts and booleans for changed HUMAN note fields.
- `PRIVATE-inbox-HUMAN-history.json`: same source-minimal data, literal false
  authority flags and explicit *manual order is not authenticated chronology*.
  
No original board hashes, local input paths, filenames, customer identifiers,
original evidence or actual question/next-action text enter report outputs.
Small cohort and suggested roles may still identify a person; **keep all
three outputs private**, not for external publication.

## Build a new three-file report

Choose 2–8 *separately saved* **complete** six-column HUMAN worksheets.
The CLI argument order is a HUMAN choice, not a verified timestamp.
Supply an **existing, empty, owner-owned mode-0700** destination outside
the original inbox source tree. All file inputs must be owner-private.

~~~sh
mkdir -m 700 ./owner-private-history
python3 assessment-disclosure-preflight/private_inbox_history.py build \
  --board ./owner-private-workroom/PRIVATE-inbox-portfolio.json \
  --revision ./owner-private-sheets/first.csv \
  --revision ./owner-private-sheets/second.csv \
  --revision ./owner-private-sheets/third.csv \
  --private-output-dir ./owner-private-history
~~~

No report file is published until all complete worksheets admit against
the exact original board, and input bytes are reread immediately before
the exclusive publish. All three outputs are created as owner-only 0600.
The source files and already active HUMAN plan are never modified.

## Reopen an existing private history without writing

Use the *same* original board and complete ordered revision files.

~~~sh
python3 assessment-disclosure-preflight/private_inbox_history.py reopen \
  --board ./owner-private-workroom/PRIVATE-inbox-portfolio.json \
  --revision ./owner-private-sheets/first.csv \
  --revision ./owner-private-sheets/second.csv \
  --revision ./owner-private-sheets/third.csv \
  --private-output-dir ./owner-private-history
~~~

The native receiver rebuilds all three expected report bytes and requires
the complete expected file inventory, current-user owner, a 0700 directory,
regular unlinked owner-only 0600 files, and exact content equality. Unexpected
files, links, changed originals or report bytes produce HOLD, never repair.
No stored original is rewritten. Exit code 2 means REVIEW_ONLY, 3 means HOLD.

## Safety and interpretation

Neither the supplied “first / second / third” ordering nor a local hash
proves when a HUMAN change happened or who made it. A changed stage is
not a verified mitigation, signed audit, source provenance or authorization.
No role suggestions count as actual assignments. All original source-owner,
independent security/privacy/browser reviews, request/grant tenant integrity
issues #177/#182/#829, genuine separate current client/operator consent with
action-time revocation and explicit HUMAN GO remain mandatory. Never treat
REVIEW_ONLY as permission to scan, dispatch, disclose or release.
