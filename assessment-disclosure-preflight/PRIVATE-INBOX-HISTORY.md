# LightUp PRIVATE source-free HUMAN revision history

**INCUBATE M3/M7 · PLAN/LAB ONLY · REVIEW_ONLY/HOLD.** This is a
local, original-source-free private coordination aid. It never executes
an assessment, contacts clients, scans assets, authenticates reviewers,
records a grant, resolves a vulnerability or authorizes a release.

## What you can do

Compare **2–8 complete original HUMAN action worksheets** saved at
different manually selected moments against **the same exact original
source-free inbox board**. The history includes all original 1–12 slot
memberships, even unchanged or currently unreviewed slots.

The read-only admission rejects output destinations nested inside any
original board/worksheet folder, changed board bytes, unknown/duplicate
CSV columns, missing/reordered slots, inconsistent SHA-256 board binding,
noncanonical stages or roles, unsafe notes, duplicate complete revisions,
unexpected output inventory, and local file ownership/mode drift.

Results are private and source-free, **not anonymous**:

- Scriptless `PRIVATE-inbox-HUMAN-history.html`: per-round stage summary,
  per-slot stage/role progression and changed-only adjacent transitions.
- `PRIVATE-inbox-HUMAN-history.csv`: complete slot-by-round statuses, proposed
  roles, original HOLD counts and booleans for changed HUMAN note fields.
- `PRIVATE-inbox-HUMAN-history.json`: same source-minimal data, literal false
  authority flags and explicit *manual order is not authenticated chronology*.
- `PRIVATE-inbox-HUMAN-latest-attention.csv`: all original slots grouped
  by the last manually supplied HUMAN stage, proposed discussion role and
  unresolved original HOLD counts; this is neither a real staff assignment
  nor an automated workflow.
  
No original board hashes, local input paths, filenames, customer identifiers,
original evidence or actual question/next-action text enter report outputs.
Small cohort and suggested roles may still identify a person; **keep all
four outputs private**, not for external publication.

## Build a new four-file report

Choose 2–8 *separately saved* **complete** six-column HUMAN worksheets.
The CLI argument order is a HUMAN choice, not a verified timestamp.
Supply an **existing, empty, owner-owned mode-0700** destination outside
the original inbox source tree. All file inputs must be owner-private.

~~~sh
mkdir -m 700 ./owner-private-history
python3 assessment-disclosure-preflight/private_inbox_history.py build \
  --board ./owner-private-workroom/PRIVATE-inbox-portfolio.json \
  --revision ./owner-private-sheets/first.csv \
  --revision ./owner-private-sheets/second.csv \
  --revision ./owner-private-sheets/third.csv \
  --private-output-dir ./owner-private-history
~~~

No report file is published until all complete worksheets admit against
the exact original board, and input bytes are reread immediately before
the exclusive publish. All four outputs are created as owner-only 0600.
The source files and already active HUMAN plan are never modified.

proves when a HUMAN change happened or who made it. A changed stage is
not a verified mitigation, signed audit, source provenance or authorization.
No role suggestions count as actual assignments. All original source-owner,
independent security/privacy/browser reviews, request/grant tenant integrity

### Native receive and reopen of a browser-composed history

Browser composition is intentionally unsigned. After explicitly downloading
the browser's source-free history JSON, move it to owner-controlled regular
0600 local storage. To turn it into the original complete four-file PRIVATE
custody packet, the **native** original-source receiver can use:

~~~sh
mkdir -m 700 ./owner-private-browser-received

  --board ./owner-private-board/PRIVATE-inbox-portfolio.json \
  --revision ./owner-private-sheets/first.csv \

  --browser-history ./owner-private-browser-inbox/PRIVATE-inbox-HUMAN-history-browser-unsigned.json \
  --private-output-dir ./owner-private-browser-received
~~~

The receiver re-admits the exact original board and every complete original
HUMAN worksheet, checks the browser's entire canonical unsigned history
against a fresh **independent native recomputation** (including boolean field
types, exact stage membership and all transitions), and publishes the normal
private HTML + two CSV files + JSON **only if the entire report matches**.
Unexpected JSON keys, duplicate decoded keys, changed input files, symlinks
or incorrect 0600/0700 owner custody return HOLD. This is *not* identity
authentication: an identical malicious or misattributed unsigned source is
still unsigned, and consent/approval is not inferred.

A saved packet can later be re-admitted read-only by running the same command
with `reopen-browser` instead of `receive-browser`; the existing private
four-file folder is not altered. Browser-original source bytes remain
unchanged, and a different browser report/source/slot order is rejected.

identical saved four-file packet from the same original source CSVs.

### Compare any two HUMAN rounds and export a source-free interval

The offline History Desk now has a separate **manual interval comparator**.
Select an earlier and a later round (not necessarily adjacent). It displays
the exact original-ordinal HUMAN status and proposed discussion-role at
both endpoints and independently indicates whether those two fields were
edited *at any intermediate round*. A change and subsequent reversal
therefore remains visible without being mislabeled as a different final
value. Private question/next-action strings are never displayed or restored;
their flags indicate **at least one edit in the chosen interval**, NOT
that the final text is different. Manual chronology is not authenticated.

The optional PRIVATE interval CSV always preserves all original slots in
original order even if the browser has the changed-only view selected.
It contains no board hash, original filenames, private notes, target names
or actual reviewer identities, and explicitly marks all authority flags false.
Treat downloaded CSV as **sensitive and unsigned**: browser Downloads
permissions and confidentiality are outside LightUp's native custody.

### Clearing the *entire* PRIVATE session

**Clear ALL private inputs and history** removes the displayed native or
browser-composed history, both original file-picker selections, in-memory
pending JSON and any active round interval. Switching to an imported native
history also clears any previously selected original board/HUMAN files.
When the source file or revision order changes after composing, the old
browser-built history preview disappears rather than pretending it still
belongs to the new originals. In-flight older file imports are rejected
rather than overwriting a newer session. The browser cannot securely wipe
its process memory or an already downloaded file; close the trusted browser
after private work and protect local downloads separately.

### Native original-source PRIVATE HUMAN interval dossier

The source-bound interval counterpart to the browser range comparator is
`private_inbox_interval.py`. It re-admits the exact original source-free
board and all 2–8 complete HUMAN CSV revisions; an interval may begin
at any earlier manual round and end at any later one. Original source-file
SHA-256 membership, complete original slot order, valid private HUMAN
note content and unchanged 0600 private input bytes are independently
admitted before publication.

To build an **original-source 0700/0600 PRIVATE three-file dossier**,
create a new empty owner-only directory outside all original input trees:

~~~sh
mkdir -m 700 ./owner-private-interval
python3 assessment-disclosure-preflight/private_inbox_interval.py build \
  --board ./owner-private-board/PRIVATE-inbox-portfolio.json \
  --revision ./owner-private-sheets/first.csv \
  --revision ./owner-private-sheets/second.csv \
  --revision ./owner-private-sheets/third.csv \
  --from-round 1 --to-round 3 \
  --private-output-dir ./owner-private-interval
~~~

The resulting `PRIVATE-HUMAN-original-interval.html` (scriptless),
`PRIVATE-HUMAN-original-interval.csv` (complete original slots) and
`PRIVATE-HUMAN-original-interval.json` are independently regenerated
only from the unchanged original board and original worksheets. Each row
distinguishes **endpoint stage/role differences** from **any intervening
stage/role edit**, including reversals. Question and next-action fields
are represented only by an *at-least-one-edit* boolean, never note text.
Manual row order is not a verified timestamp. None of these reports
contains original target data, file paths, board digests or reviewer IDs.

To reopen the stored dossier **read-only**, use the *same original files
in the same manual order* and same round limits with the `reopen` action
and existing output folder. The receiver requires the exact entire
three-file output inventory, 0700/0600 owner-only ownership, ordinary
unlinked files and byte-for-byte equality; unexpected files, symlinks,
changed inputs or saved reports return HOLD without changes.
The browser's unsigned interval CSV is not itself a native source-bound
dossier; original private input custody remains mandatory. Exit code
2 is REVIEW_ONLY and code 3 is HOLD, never authorization.

The native and browser interval CSV downloads use matching **field names
and ordering**, including all original slots, original HOLD counts, selected
round bounds, endpoint-versus-intermediate HUMAN edit flags and explicit
false authority columns. They remain distinct unsigned local outputs: only
the native path re-admits every original private source and stored report.
