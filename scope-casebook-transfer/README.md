## Operator workflow

Open [standalone.html](standalone.html) **locally in a current secure-context browser**, or open `transfer.html` with both adjacent `transfer.js` and `transfer.css` files (when local browser CSP permits local relative assets). The portable standalone version has SHA-256 CSP-pinned inline CSS and JavaScript, zero external dependencies or fetch.

1. Use the **original** authenticated Casebook producer to capture `casebook-01.json` through `casebook-NN.json`, contiguous from 01, up to 12. Those originals come from the original held branch, not from this new transport. Optionally include the exact generated current-HUMAN-only `workroom-current-template.csv` (not the historical multi-moment `private-human-review-template.csv`). Do not use client data on a shared/untrusted device.
2. In the local transfer page, select those files (each max 4 MiB; all files max 12 MiB; max 13 entries). Supply a strong distinct password of at least 12 Unicode characters. Acknowledge this is **not authorization**. Click **Maak versleutelde PRIVATE overdracht**. It immediately downloads `lightup-casebook-private-transfer.lupt` as an opaque octet-stream.
3. Move the encrypted file over your approved secure human handoff channel. Communicate the password **separately** using an approved route. The password is not saved by this application, so losing it loses access to the handoff. Do not treat encryption as evidence of who produced the original snapshots.
4. On the receiving trusted offline device, open the same standalone page, select the encrypted `.lupt` file and enter the password. The encrypted file may have been safely renamed by your browser (for example, adding a duplicate-download number); the **authenticated envelope and original bytes**, not an unauthenticated filename, determine whether it can be opened. The entire ciphertext is authenticated and the complete canonical v1 payload re-admitted before the page asks for confirmation. Wrong passwords, changed bytes, unexpected names, repeated names, changed SHA-256, missing chronology ordinals, unknown extra fields and over-size payloads are refused **without replacing the previously loaded local workset**.
5. Only after manual confirmation, use the per-record **Exporteer exacte bytes** buttons to recover the original selected bytes as downloads. Reopen those files using the **original trusted Casebook/history validators**. This tool never issues a grant or modifies the LightUp database. Its digest is an internal transport continuity check, **not source authentication**.
6. For a second approved HUMAN recipient, enter a different local password under **Beveiligde dooroverdracht** after loading or restoring a workset. The app performs a fresh AES-GCM encryption **directly from the in-memory original bytes**, with a new salt and nonce, downloading a new encrypted file **without producing extra plaintext exports**. The previous encrypted file and the original source files are not overwritten. Human review of the new recipient and channel remains necessary.

## Integrated source-bound HUMAN follow-up desk

The same offline transport now includes a fourth panel, **Huidige HUMAN dossiers**, automatically populated from the **last selected original Casebook**. It presents the original source-declared engagement ID, original next review action and attention category alongside three editable **HUMAN-only** fields: stage, follow-up route and blocker. Filtering/selection is local and never authorizes execution.

- The private desk includes original-source declared change indicators (first observed, source attention/action changed, source status changed, no latest observed change), with in-tab private ID/action search, original HOLD-only filter, source-change filter and HUMAN-unreviewed queue filter. The original source observation compares each case's **two last appearances within only the selected snapshot sequence**, not independently trusted dates or verified changes. An absent case is never declared fixed or revoked.
- All current cases are constructed in the **original source `scope-casebook-history/history.py::case_queue` ordering**: HOLD/pending/window source attention categories, recorded attention changes across selected snapshots, declared grant count and stable original engagement ID. No original source owner code is changed, and the sorting is **not a verified risk priority**.
- If the operator supplies an original `workroom-current-template.csv` from the same source history, the transfer now admits it **against the exact last source**. Its six original columns, complete original current case set, row ordering, recorded original actions/attention and all three HUMAN enum values must match pinned `workroom.js` contract. An older source snapshot's CSV, a different client's snapshot, wrong row order, removed/additional case, edited source label or unknown HUMAN state causes a **whole-batch HOLD before encrypt or workset replacement**.
- If no HUMAN CSV was supplied, the app shows a new **local HUMAN draft** with default labels; it does **not** pretend this was produced, verified or signed by the original Casebook. Once the operator explicitly chooses **Sla HUMAN-opvolging lokaal ... op**, the app prepares the current exact source-bound `workroom-current-template.csv`, hashes it and stages it atomically *only in its private in-memory workset*. It never edits the original Casebook JSON.
- When an operator edits a previously selected HUMAN CSV, only that CSV is replaced; the original source bytes are copied before old in-memory references are released. The package/download/rekey controls can then transfer the updated PRIVATE bytes under fresh authenticated encryption. Explicit plaintext recovery remains manual and separate.
- Reopened encrypted packets must pass exact SHA-256 transport admission **and** the current HUMAN-to-source binding before the user is asked to replace their workset. Failed binding leaves the previously loaded source and HUMAN state untouched. Existing original original Casebook production parser remains authoritative for real source integrity.

The module is contained in [human-board.js](human-board.js); the deterministic portable `standalone.html` now bundles and independently CSP-hash-pins both product scripts plus CSS. It uses no external data, cookies, localStorage, scans, approvals, revocation APIs or network calls. Original IDs and labels may be PRIVATE and are shown only inside the private local page.

## Design boundary

- Offline WebCrypto `PBKDF2-SHA256` with 310,000 iterations, cryptographically random 16-byte salt, `AES-256-GCM` with a fresh 12-byte nonce for every export. Nonces and salt are chosen by the browser CSPRNG; original files are encrypted **without any lossy text decoding**.
- The encrypted v1 envelope is strict canonical JSON, carries an authenticated encrypted v1 body with exact original byte lengths/digests, and is bounded to 26 MiB. Unknown/duplicate keys or extra properties fail canonical re-serialization, before passwords are used. Expected file names/contiguous ordinals, no duplicate entries, exact SHA-256 byte rechecks, byte limits and a single all-or-nothing in-memory handoff are required.
- No analytics, HTTP(S), network, sessions, browser storage, service worker, authentication, grants, target use, model calls, clipboard reads or automatic plain file persistence. The portable HTML embeds local JS/CSS with **hash-pinned CSP**; all displayed filenames are pre-admitted fixed patterns and inserted as text nodes. Downloads are explicit and use `application/octet-stream`, not HTML execution.
- Clear releases references and overwrites in-memory typed byte buffers on a best-effort basis, but JavaScript engines/browser caches cannot guarantee physical memory erasure. On shared machines or after dealing with private inputs, close the browser and follow normal endpoint security/retention policy.
- The app now performs **bounded shallow original-source admission** on each selected Casebook v1 JSON at initial packing AND after decryption: valid UTF-8, no duplicate JSON keys anywhere in a source document, exact expected top-level source fields, original REVIEW_ONLY status/source label, all six authority flags literally false, exact nonempty printable original client ID, and **one identical source-declared client ID across all selected Casebook snapshots**. Failure refuses the full candidate batch. The optional workroom CSV is opaque and NOT independently verified; it is only encrypted as chosen bytes.
- **These are shape and bundle-consistency checks, NOT authenticated original source validation.** Sources can be old, altered, internally incoherent or forged with matching client IDs. A successful decrypt/digest or a matching self-declared tenant ID does **not** prove original producer identity, actual tenant ownership, approved request, current grant, trusted timestamps, independent operator/client consent, action-time revocation or a verified security finding. Use the complete original Casebook/history source validator and current authorization boundary before any claim or action.
- The local transfer password and endpoint security are critical. AES-GCM ciphertext can protect at-rest data against someone without the password; it cannot make a compromised browser or endpoint trustworthy. Exported plaintext downloads remain sensitive. Small data sets may be re-identifiable.
