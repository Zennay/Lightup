## Optional offline two-source lab declaration comparison

The operator app can now open a second **already-produced** original PRIVATE lab-result JSON for a human-only side-by-side source declaration review. It requires exact same original scenario literal and exact same set of 1–16 declared target strings but a distinct run ID. Both source schemas are independently admitted before the comparison board changes; failures leave the existing board and original human notes intact.

The comparison uses the literal original target + capability ID + check ID as a **source-declaration grouping heuristic**, not verified vulnerability or client identity. When multiple source findings have the same grouping tuple in either document, that group is **AMBIGUOUS**, never silently paired. Every non-ambiguous group is classified only as (1) reported solely in A, (2) reported solely in B, (3) source description/severity/retest/fix changed, (4) source evidence **summary text** changed, or (5) source descriptive fields equal. Evidence ID changes are not proof of source equivalence or provenance. Missing B entries are **not fixed or closed findings**; B-only entries are **not verified new vulnerabilities**; unchanged source descriptions are **not a trusted match**.

The separate interface provides original A/B report ordinals and two side-by-side private source descriptions (severity, title, retest label) with individually expandable source impact, mitigation and unverified evidence-summary text. Ambiguous repeated source keys are **not** represented by a single arbitrary example. It includes filters and 100-row pages, plus **Open original A HUMAN follow-up** for each unambiguous A declaration: the current human review table is opened at its original ordinal and focused, without carrying a single B field or changing original A evidence. Ambiguous B/A groupings have no automatic link. The private original details never enter anonymous exports. Only anonymous source check-group totals and four literal-false authority flags are exported. Target URLs, original scenario IDs, source hashes, raw evidence, finding IDs, client/engagement details and report notes are never exported. The comparator does **not** carry over human notes or alter either original source.

## Source/privacy boundaries

* File input is explicit local browser selection, capped at 8 MiB, with fatal UTF-8 decoding and strict duplicate-key JSON parsing. Source errors and invalid returns never partially apply.
* Human review returns have fixed keys, enumerated stages/groups and limited free text. Source bytes are **never** copied to a return, and output only occurs via a human-initiated download.
* Browser-local file inputs cannot enforce Unix no-follow or filesystem mode rules. The original separate lab-inspect CLI is the source owner’s private file admission path. This browser only handles a deliberately opened file; it cannot establish authenticity.
* A source-provided benchmark_case must declare is_lab true, authorization null and the same run_id. This is an untrusted structural declaration, **not proof** of lab isolation or permission.
* Previews and standalone record/context benchmark envelopes are intentionally rejected; they have no finding-by-finding review semantics.
* Source-provided severities, retest state, evidence summaries, original targets and even source hash are **not independently verified facts**. Missing source findings are never automatically repaired. Edits only affect local human notes and not the source.
* If the file browser does not expose WebCrypto SHA-256, original data can still be privately viewed but source-bound private save/resume is disabled; no fabricated fingerprint is accepted. Human notes remain in memory unless deliberately exported. Unsaved changes trigger a browser leave warning. Use an appropriately protected offline channel for any PRIVATE file.
