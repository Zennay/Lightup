## Structured evidence-dossier preparation (not evidence authentication)

Each imported original finding now has an editable, local and explicitly **unverified human evidence dossier**. The four separate reference slots are the original patch/change ticket reference, deployment/rollout reference, rollback/recovery reference, and separately approved retest-request reference, plus a longer free-form question for the human reviewer. The browser never reads those referenced systems, opens links automatically, fetches raw evidence, validates the content, approves a retest or updates the original finding.

The operator dashboard counts incomplete versus four-reference dossiers and offers a **severity-by-severity evidence-readiness matrix** with missing-reference categories and human follow-up candidates. Its aggregate CSV contains only original severity categories and numeric counts, without original findings, customer names, hosts, notes or reviewer identities. It is neither an SLA nor a privacy guarantee if shared with outsiders; disclosure still needs an independently approved channel.

Original private Evidence Review drafts now use **schema version 2**, preserving the bounded evidence dossier inside each human review entry. The new importer still accepts original version-1 review JSON packets and initializes their missing dossier fields as empty. A version-2 file missing its required evidence section is rejected atomically. Older version-1-only versions of this offline app reject version 2 rather than silently drop newly introduced evidence fields. On a source refresh, all local evidence references, reviewer comments and coordination stages are retained **only** for five-field-exact unchanged original findings; changed and new findings start with empty dossiers and absent findings remain unverified in the revision register.

Private team handoffs use **schema v2** including these dossier fields in both the JSON body and the source+local-baseline checksum, so returned evidence notes can be merged only when the original local review state has not changed. A returned v1 team packet still loads as before without discarding an existing local dossier. All returned documents are unsigned, independently recipient-verified human drafts only, never authentication or verified remediation.

## Actionable human follow-up agenda (non-authorizing)

## Trust boundaries
- The original Casework parser, source normalization, canonical content SHA-256 and draft v1 loader are **reused** from original owner source. A source-digest-compatible local SHA-256 fallback works when WebCrypto is unavailable on file:// offline pages. SHA is an unsigned correlation fingerprint, **never authentication or a signature**.
- No external assets, network calls, file upload, browser persistence, real finding mutation, granted scope, client consent, scanner execution or verified retest.
- A local “completed” or “ready” status is not evidence of a fix. A source-reported “fixed” status remains historical, not an independently proven currently valid retest. Missing findings in later exports are not proof of repair.
- Real evidence files are intentionally **not** imported or stored. Leave sensitive artifacts in the authorized client workflow; never enter passwords, customer secrets or raw exploit evidence as references.
- Private source exports and Markdown handoffs may contain confidential details. Protect and share only via independently approved channels. Aggregate source hashes may correlate separate documents.
- Invalid source does not replace the current in-memory board. Human notes are kept only in the open tab until explicit private export.
