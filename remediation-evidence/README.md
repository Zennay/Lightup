## Human team routing and source revision register

The Evidence Board now includes a usable **single-team private repair handoff**. Select one locally declared original Casework owner (or, when no Casework owner exists, one local reviewer/team) and explicitly confirm the recipient scope. Export a detailed private JSON or spreadsheet-safe CSV with only that group's original source findings, original remediation text, local casework dates/actions/blockers, human evidence references and follow-up suggestions. Unassigned work is an explicit separate selection. Group names are locally declared, **not authenticated LightUp identities**, and no team receives automatic access. Each CSV text cell is escaped as a literal and spreadsheet formula prefixes are not executed. No ticket is created in any external system.

The board also maintains a **bounded last-12 human-confirmed original source revision register** across refreshes. Original added/changed/absent finding IDs and the original five changed-field names are retained with unsigned source content hashes; absent original findings always remain **UNVERIFIED**, never repaired by inference. The register is saved inside the same private Evidence Review JSON and reloaded only when its SHA chain ends at the exact currently imported original source. Older packets without a register remain valid. Separate exports provide (a) a sensitive source-ID CSV for approved follow-up and (b) an aggregate-only chronology excluding finding identifiers and notes.

The operator can search finding IDs, original titles/remediation text, original Casework owner and blockers, or local reviewer/reference/action. Filters can target a specific locally declared team and focus on source regressions, overdue cases, blocked plans, human retest requests or contradictions; the board sorts by original severity, local due date or human follow-up urgency. Bulk local review updates use exactly the filtered set, with a separate confirmation. These are human productivity tools, **never** authenticated approvals or automatic work orders.

The local status board and routing group list are cleared from the DOM when the user chooses to forget all data. Original Casework branch content stays immutable.

## Trust boundaries
- The original Casework parser, source normalization, canonical content SHA-256 and draft v1 loader are **reused** from original owner source. A source-digest-compatible local SHA-256 fallback works when WebCrypto is unavailable on file:// offline pages. SHA is an unsigned correlation fingerprint, **never authentication or a signature**.
- No external assets, network calls, file upload, browser persistence, real finding mutation, granted scope, client consent, scanner execution or verified retest.
- A local “completed” or “ready” status is not evidence of a fix. A source-reported “fixed” status remains historical, not an independently proven currently valid retest. Missing findings in later exports are not proof of repair.
- Real evidence files are intentionally **not** imported or stored. Leave sensitive artifacts in the authorized client workflow; never enter passwords, customer secrets or raw exploit evidence as references.
- Private source exports and Markdown handoffs may contain confidential details. Protect and share only via independently approved channels. Aggregate source hashes may correlate separate documents.
- Invalid source does not replace the current in-memory board. Human notes are kept only in the open tab until explicit private export.
