# LightUp PRIVATE Scope Disclosure Desk

**Status:** INCUBATE M3/M7 · PLAN/LAB ONLY · DRAFT/HOLD. Offline HUMAN-only helper; not an authorization product, security guarantee, or declassification.

## Use

**Fastest:** open or distribute the already generated **PRIVATE-disclosure-standalone.html**; the recipient can independently open **PRIVATE-verify-standalone.html**. Both files embed the complete CSS and JS with exact SHA-256 CSP pins, require no adjacent assets, and use no external resources. Alternatively keep index.html, desk.css, desk.js, verify.html and verify.js together in one directory.

For repeatable packaging, run the Python standard-library **package.py** with no flags to verify both committed standalone assets byte-for-byte against the original source. The optional --output-dir PATH writes exclusive private 0600 portable copies into an existing directory without overwriting existing files. This does not run QA suites. It does not require a server, network, model, account, scanner or installation.

1. Choose a HUMAN-owned PRIVATE UTF-8 TXT, CSV, JSON, MD, LOG, PEM, KEY or ASC (2 MiB maximum). Invalid UTF-8, NUL/control characters, invalid filename shapes, empty or oversized input HOLD.
2. Add 1–30 exact case-sensitive sensitive values to mask, 3–128 characters each. Each must occur in the original text. Values are not echoed in the rule list.
   Optionally select specific LOCAL categories and click **Add all selected suggestions as masks**. The human-triggered suggestion engine searches Bearer/credential/JWT/API token patterns, email addresses or HTTP(S) URLs/IPv4-like addresses, according to your choice. New exact literal matches are added atomically within the original 30-mask ceiling and never displayed in the rules list. A large, invalid or over-capacity selection HOLDs without adding partial masks. This is a convenience feature, **not** comprehensive secret detection, contextual privacy review or approval; check the entire transformed output. For multiline PEM and PGP PRIVATE KEY BLOCK documents, the source holder can explicitly enable **Complete multiline private-key removal**. It removes *whole* recognized BEGIN-to-matching-END blocks (up to 16 blocks, 256 KiB per block) before applying ordinary literal masks; incomplete, nested, overlong, or ambiguous blocks HOLD without generating a private export. This is a source-owner-selected destructive disclosure transform, never a grant, authorization or proof of safe declassification. Each enabled whole-block category uses one of the 30 available masking-rule slots. Original-source PRIVATE KEY headers now require complete recognized key-block removal even if someone tries to mask just the BEGIN line: header-only replacement cannot remove the underlying key bytes, so it always HOLDs. Unrecognized, nested or incomplete private-key source headers likewise HOLD instead of allowing a truncated or marker-free secret to be exported. Do not copy private-key blocks into single-line rule fields.
3. Prepare a redacted preview. A single deterministic left-to-right replacement pass uses [REDACTED]. Longer overlapping mask alternatives take precedence. Output is bounded to 8 MiB.
4. Review **every** 8,000-character page. A bounded, case-sensitive **find in redacted copy** field can jump to a private matching page without scanning, indexing or displaying the original unredacted text. Searches are local, not persisted, and intentionally capped. Opening a match counts only that displayed page, not the entire document. Heuristic hints may flag emails, URLs, credential assignments, private-key markers and IPv4-like addresses. No hits does **not** prove safe sharing. Residual Bearer tokens, JWT-shaped values, GitHub/API token-like values, AWS access-key identifiers, credential assignments or PRIVATE KEY markers cause a hard export HOLD: return to the mask rules until these heuristics no longer appear. Other possible sensitive patterns remain a HUMAN review warning.
5. Explicitly check two review warnings and type EXPORT REDACTED. Export is locked until all pages have been opened. Confirmation resets on changes and after any export.
6. Download the full redacted copy as .txt (even for structured originals, because substitution can break JSON/CSV syntax), or download the separate PRIVATE human counts receipt. The receipt contains redacted SHA-256, byte/replacement/mask counts, remaining heuristic counts, and six literal false authority flags. It excludes original source filename, original SHA, original text and mask values.
7. Clear application session when finished. Downloaded files remain on disk; browser/OS memory erasure is not guaranteed.

The resulting text may be used as OPTIONAL HUMAN-reviewed source for the existing separately owned PRIVATE encrypted scope courier. This tool does not read its encrypted format, execute it or certify that the redacted material is safe to disclose.

## Recipient continuity

Open **verify.html** or the completely bundled **PRIVATE-verify-standalone.html** with the received redacted .txt and its separate PRIVATE counts receipt .json. It reads both locally in memory and enforces exact bounded companion JSON serialization, schema, non-authority flags, redacted SHA-256 and byte length. After matching, it independently recomputes the *same source-code privacy hint categories* against the actual received text, compares those counts with the received receipt, and exposes the entire received text in 8,000-character, read-only pages for private human review. A bounded case-sensitive local find navigates matching positions in the received redacted copy, and direct page navigation avoids repeated clicks on large files. Neither control reads the original unredacted source or changes the receipt. A jumped-to page counts as displayed only when it is actually shown; every page must still be displayed before the recipient can export a HUMAN reply. Remaining credential/JWT/API-token/Bearer/private-key hints yield **HOLD / CONTENT ATTENTION** even when the bytes match. Other matches yield only **MATCH / REVIEW ONLY**, not approval or authenticity. Changing either file clears the comparison and reader. A mismatched, malformed, duplicate-key, oversized or invalid UTF-8 receipt causes HOLD. This cannot detect a malicious sender who changed both files; confirm sender identity and current permission through a separately authenticated channel.

## Two-way PRIVATE HUMAN follow-up

Once recipient file equality and independent residual hint checks complete, the recipient can view the **entire** file in 8,000-character pages. Only after all pages were displayed and a new explicit HUMAN acknowledgment may the recipient export a bounded PRIVATE JSON reply. Possible credential, JWT, GitHub/API token, AWS-key, Bearer or private-key leftovers restrict the only allowed proposed outcome to **request more masking**. Otherwise the recipient can request context or return read-only notes. Notes are optional, at most 800 UTF-16 code units. The sender and recipient both reject recognizable credential, token and private-key patterns within a HUMAN note, and reject C0/C1 controls plus invisible bidi/direction-format marks (including zero-width spaces and BOM) without silently rewriting the text. Ordinary line breaks and multilingual joiners remain supported. False negatives and contextual private identifiers remain possible. Never include secrets or private client identifiers. Every reply uses the actual redacted text SHA-256 and exact byte length, has a canonical fixed field order, and all six identity/consent/action/release booleans are literally false. The reply is **not** a cryptographic signature, authenticated sender proof, grant or client approval.

The source holder opens the original PRIVATE source, re-stages the intended masks and prepares its exact current redacted preview. Only then does the disclosure app enable **Read source-bound HUMAN feedback**: it accepts one local JSON reply at most 4 KiB, requires exact canonical serialization, source hash and size equality, known HUMAN-only outcomes, bounded notes and all false flags. Any changed source, change of selected reply during read or invalid structure HOLDs. Feedback is displayed as plain, read-only text and **never auto-applied** to masking rules, source files or authority. Source holders must establish the recipient's identity separately through a trusted channel; two matching hashes and a freely editable JSON do not prove that identity. Both source and feedback may remain sensitive; handle them as PRIVATE.

## Security and limitations

- CSP default-src none, connect-src none, no external assets; sibling local CSS/JS only. No fetch, WebSockets, cookies, localStorage, persistence, model, scanner, grants, targets, server actions or automatic writes.
- Masks are literal only. Unicode confusables, normalization, sensitive context, redacted semantics, non-text formats, encoded secrets and unknown fields can remain. The heuristic hints are non-exhaustive and may be wrong.
- The original is never overwritten. Download requires a deliberate user action. File SHA-256 proves only matching bytes, not authenticated source identity, approval, actual client/operator consent or revocation.
- Browsers and extensions on compromised machines may access locally loaded content. Use a trusted private environment, review the **entire** output, and verify the recipient separately.
- This helper never grants assessment authority, authorizes active targeting, verifies vulnerabilities, fixes findings or proves privacy clearance.
