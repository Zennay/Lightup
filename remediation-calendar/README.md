**Product phase: INCUBATE M3/M7 · PLAN/LAB ONLY · DRAFT/HOLD.** This isolated branch adds a genuinely usable local calendar and work queue on the original immutable Casework owner snapshot, but does not permit deployment, release, grant issuance, assessment, remediation validation or scanning.

## Operator workflow

Open [index.html](./index.html) from a **complete local repository checkout** with the original sibling `casework/remediation-engine.js`, or build the single-file `standalone.html` with `python3 remediation-calendar/package.py` from that checkout. The packager refuses changes to the original pinned Casework source SHA-256 `c293c564ecb11434e45423d244b7beba599b6afe3ebbc85121882e91b8aa1225`; it embeds the exact original JavaScript, its own calendar JavaScript and CSS with individual SHA-256 CSP script/style pins. The compiled HTML uses `connect-src 'none'`, no external runtime files, no network, cookies, local storage, sign-in or scanners.

1. Independently obtain a **real, authorized** LightUp original findings summary for a specific client/engagement using the original authenticated export. In the unchanged [original Casework app](../casework/README.md), import it, coordinate owners and due dates, then save the original **PRIVATE Casework v1 JSON**. Do not substitute synthetic notes for valid original authentication and consent.
2. Open the Calendar, confirm the intended **exact client/engagement** separately, and select the private Casework JSON. It admits up to 2 MiB; rejects duplicated JSON object keys, unknown or missing top-level/finding/case fields, noncanonical original Casework statuses, authority claims, absent/duplicated source findings and invalid source SHA fingerprints. It uses the **unchanged original Casework v1 validator and SHA-256 canonical source digest**.
3. Review the human due-date queue. Filter by original severity and locally recorded human blocked, overdue, missing-owner and retest-follow-up stages. Original `retest_status` remains read-only. Missing source records are not interpreted as repaired, and missing due dates never become artificial deadlines.
4. Export a tentative **all-day .ics calendar** for the visible queue or all scheduled open cases (maximum 350). Export is held until explicit receiving-calendar/channel confirmation. Default output suppresses finding IDs, customer titles, owner and notes; **PRIVATE mode** intentionally includes finding ID, title, owner, next action and original retest state in the calendar event description. Even the redacted mode can expose risk-category counts and dates, so do not upload it to a public or personal calendar. Each event has `CLASS:PRIVATE`, `STATUS:TENTATIVE`, no attendees, URL, automated notifications or network operation, and a source-bound opaque SHA-256 UID for stable re-import identity.
5. Export a separate **aggregate-only workload CSV** by severity, reporting counts of open human plans, blockers, due, overdue and independent-retest follow-ups. No original titles, IDs, owner names, dates, free-text notes, source hash or customer metadata appear. `Clear private workspace` removes in-memory application state; already downloaded or imported files must be handled separately.

**Calendar date policy:** only existing local human `due_date` in 2020–2100 is exported. Events are one full UTC calendar day with an exclusive next-day end. Completed/deferred human plans are not exported. Date arithmetic is independent of a browser's daylight-saving timezone. No contractual SLA, authorized retest window, verified fix, or actual meeting invitation is produced. Unknown/unsupported dates cause the selected calendar export to HOLD rather than being truncated silently.

**Boundaries:** all inputs and outputs are unsigned, private, user-supplied offline coordination material. Neither the original SHA hash nor the original export proves its author, freshness, client or operator identity, current consent or non-revocation. The browser is not a replacement for authoritative LightUp controls. No QA/regression suite is added or executed. Do not merge to main or deploy until original exact-head hosted and permanent named VPS CI, source-owner/security/privacy approvals, original #177/#182/#829 gates, authentic independent client/operator consent with action-time revocation and explicit HUMAN GO.
