# Private offline workspace content continuity

**INCUBATE M3/M7 · PLAN/LAB ONLY · DRAFT/HOLD · NO GO.**

A complete newly generated original-source assessment workspace ZIP now includes a new private `private-workspace-content-map.json` (schema `lightup.assessment_portfolio_private_content_manifest.v1`). This is a bounded, original-source-neutral **byte correlation manifest** for the generated human interface and report files in the same ZIP: scriptless workspace home, original human attention queue, interactive private human Review Studio, hypothetical Capacity Studio, source-bound private bindings, counts-only original reports and the original START-HERE text.

At creation, `portfolio.package` hashes each generated component's exact bytes using SHA-256, records its exact member name/length/digest in deterministic order, rejects malformed/oversized parts, and places the content map alongside the originals. Both `one_command.py` and each complete next workbench from `review_cycle.py` get this document automatically.

At explicit return or continuation, `workspace_return.py` checks the bounded ZIP filename whitelist, duplicate/encrypted/compressed member rejection, complete original agenda source membership and literally false permission claims, and now also **verifies each mapped local interface/report component against its recorded byte digest** before accepting new human proposals. A removed, renamed, truncated, changed or inconsistent member causes whole-packet HOLD instead of quietly using a partial previous workspace. New bundles with this document must be complete; the source map and original human agenda themselves are separately bound against genuine operator-supplied unchanged original manifests and choices and re-rendered byte-for-byte. Previous legacy original-source workspaces without the content map remain readable using their original strict source/agenda gates, but do not gain retroactive content-integrity claims.

The map is **unsigned and stored alongside the content**. It is not an authenticity signature or tamper-proof attestation against an attacker who can rewrite both map and ZIP, and must never be treated as client permission, current operator identity, source authority, verified findings, approval, remediation success or authorization to execute. Do not share the private complete ZIP as an aggregate. Small cohort summary counts require human privacy review. No network, scanner, grant, target, model, process execution or customer data is used by this feature.

This feature uses exclusively the already isolated `assessment-portfolio/content_map.py` and its existing privately owned ZIP builder/reader. Original release gates, separate actual client/operator consent with at-use revocation, source-owner and independent security/privacy review, exact-head hosted/named VPS CI and HUMAN GO all remain mandatory.
