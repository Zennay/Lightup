# LightUp Finding CSV → PRIVATE HUMAN Review Desk

**INCUBATE · M3/M7 PLAN/LAB ONLY · DRAFT/HOLD.** Complete independent offline review interface for the **existing tenant-authorized** five-column LightUp finding CSV export. This is an isolated new-only companion, not an export endpoint, assessment runner, evidence acquisition flow, security verdict or authorization system.

Open **[standalone.html](./standalone.html)** as a single complete portable local application on a **trusted private machine**, or open [index.html](./index.html) alongside adjacent app.js and style.css. Both versions provide the same HUMAN workflow with no private source data built in. The standalone has no companion-file links or external dependencies; [build.py](./build.py) deterministically assembles it from the original five source assets (index.html, app.js, vault.js, revision.js, style.css) using SHA-256 hash-only script/style CSP. It refuses an existing output path and publishes a new local file with restrictive permissions. Rebuild after changing source files, never edit the generated portable app by hand. No installation, server, third-party asset, cookie, localStorage, fetch/XHR, telemetry, worker, permission or network call. Content-Security-Policy denies connections, frames and objects. Controls are keyboard accessible and usable on smaller screens.

## Actual product flow

1. Obtain an already authorized finding summary from the **original authenticated client/engagement selection service**; the tool never selects a tenant or authenticates the export. Existing exporter source-owner branch [#1611](https://github.com/Zennay/Lightup/pull/1611), the Unicode preflight stack and authorization fences remain unchanged.
2. In a trusted private browser open index.html and choose the canonical UTF-8 CSV. Import is **atomic**: reject >2 MiB, >128 findings, malformed quoted CRLF/column shape, invalid fields/enums, duplicate exact or NFKC-equivalent IDs, Unicode control/format/private/unassigned/separator characters and compatibility-obscured formula prefixes. Validate **all rows before showing any**. An invalid second import preserves the existing workroom. No external URLs or target information are imported.
3. Review in source severity order, search or filter by severity, HUMAN stage, assigned/unassigned HUMAN owner and tentative due window (overdue/today/next seven days/unscheduled), and order by source severity, original ID or due date, and stage optional human-only contact, due date and note. For many findings, a deliberate confirmation applies a selected HUMAN stage **only to the currently visible filtered queue**, while preserving existing contacts, dates and notes; an immediate one-step undo restores only those bulk stages, and any subsequent individual HUMAN edit discards that undo. Form fields not yet applied trigger warnings before navigation, draft export, bulk staging or source replacement. Those choices never update original CSV, retest status, durable findings or original source. The human_reviewed stage means only that a person marked local follow-up; **it does not mean fixed, approved, retested or securely closed**.
4. Export a **PRIVATE HUMAN journal JSON** after explicit confirmation; it includes finding IDs and local contacts/notes, so it belongs in controlled storage. It binds to the exact raw imported CSV byte SHA-256, complete row count and exact ordered ID sequence. Reopen the same tool-generated canonical journal on identical source to atomically restore HUMAN choices. A different source, malformed/overlarge field, swapped IDs or unknown authority claims reject. SHA-256 is **unsigned** and does **not** authenticate source, author, consent or confidentiality. JSON is **not encrypted**: keep private; never send as anonymous handoff.
5. Download an optional **PRIVATE scriptless HTML next-action brief** for the currently visible filtered findings (optionally only HUMAN-updated ones). It includes original finding IDs, titles, source-declared severity/retest/remediation and current local HUMAN owner, due date, status and notes. The brief uses HTML-escaped values and a hash-pinned static CSS CSP, no scripts, external assets or network. It is source-byte-hash labelled **but not signed**, so it cannot authenticate the creator or verify any security result. Treat it like confidential records: open or print only on a trusted private device and never send as an anonymous artifact.
6. If separately approved, export a tentative PRIVATE all-day calendar (.ics) for the visible HUMAN-updated findings with actual proposed dates. The offline handoff includes **no original finding ID, target, title, severity, remediation, owner, source digest or note**; it only contains random local event UIDs, event dates and a uniform provisional HUMAN reminder text. The local app does not call calendar APIs, invite attendees or reserve appointments. Importing a .ics into a calendar could automatically sync to a third-party provider, so ask for actual private-calendar permission first. It never schedules retests, scans or remediations.
7. If separately approved, export **counts-only JSON**: severity/stage totals and tentative overdue counts, without original finding IDs, title, remediation, source hash or HUMAN owner/notes. **Small cohort counts can be identifying/sensitive.** Neither a counts file nor button press creates actual disclosure approval.

## Optional encrypted PRIVATE journal continuity

Use the password field before **Save encrypted PRIVATE journal (.luej)** or **Open encrypted PRIVATE journal**. Native WebCrypto derives an AES-256-GCM key using PBKDF2-SHA256 at 600,000 iterations with a fresh random 16-byte salt and random 12-byte nonce for every new file. The strictly versioned portable envelope contains only ciphertext, algorithm identifiers, salt, nonce and iteration count, not plaintext finding IDs, notes, source digest or passphrase. During memory-only encrypted resume, an exact canonical envelope and GCM authenticated ciphertext are admitted before the original strict CSV-hash/row-count/ID/HUMAN-enum admission; a rejected file never replaces existing local data. The password field clears after every operation. The passphrase must be unique, long and remembered separately; losing it makes the journal unrecoverable. Plaintext export remains an explicitly separate legacy option, not the encrypted default. WebCrypto support in the selected trusted local browser is required. Password-based file encryption does **not** independently verify authorship, actual client/operator identity, review provenance, consent or security outcome. A machine with compromised browser or weak passphrase can still expose data. Do not give a passphrase or encrypted journal to an unapproved recipient.

## Source snapshot continuity: never treat missing as fixed

Under **Review a later source export**, choose a second, **separately authorized** canonical LightUp CSV from a source owner. The app admits the entire new file first and compares **literal five-column records by original finding ID** against the currently loaded source: unchanged / changed source text or claimed severity or retest / newly appearing / no longer appearing. The preview also displays the specific literal source fields that changed (including before→after source-declared severity and retest labels), separate rows newly present and rows absent from the selected file. It offers an optional **anonymous delta totals JSON** with unchanged/changed/new/absent counts only, subject to separate disclosure approval; no source digests, IDs, customer, text, notes or alleged security verdict. The two file hashes are *unsigned* and prove neither that the files came from the same authenticated tenant nor that the selected second file is newer.

Before applying a source transition, the operator chooses one of two explicit HUMAN-only policies for changed records: **reset** stage/owner/date/note to unreviewed (default), or **retain** previous HUMAN contact/date/note but force stage to *needs_evidence*. Exactly unchanged records keep their HUMAN fields, and newly appearing records are unreviewed. Records not present in the selected incoming CSV never constitute fixed findings, verified retests, client revocations, deletions, or a risk reduction.

The old HUMAN details for changed or absent records are preserved in a separate **PRIVATE previous-source revision archive**, including old original finding IDs/titles/source-declared severity/retest and previous HUMAN stages/owners/dates/notes, plus the two exact source hash labels, human-selected carry policy and anonymous delta counts. This archive is not anonymous; only a separately authorized owner can download it. It is retained in the new optional encrypted *complete* .luew workroom. Plaintext .json HUMAN-only journals and HUMAN-only .luej files intentionally capture only the active CSV and do **not** include the prior-source archive, so save the complete encrypted workroom to preserve old HUMAN details.

Historical chains are bounded to **three transitions or 512 KiB** of PRIVATE archived HUMAN data. If full, the next revision is refused without changing the current source or silently dropping prior records; retain the current encrypted complete workroom and separately authorized PRIVATE archive before deciding how to continue. The prior record is not an authenticated timeline: source-order selection is a HUMAN declaration, not network-time provenance.

The original exporter, source-owner permission checks, scope/authorization, durable remediation state, targets, models, scanner, CI and tests are not modified by this feature.

## Complete encrypted PRIVATE source + HUMAN workroom

The **Save encrypted complete workroom (.luew)** action combines the *exact original admitted UTF-8 CSV bytes* with the exact SHA-256-bound current HUMAN journal **inside the authenticated AES-256-GCM ciphertext**. It keeps no plaintext intermediate file, sends no request and uses fresh PBKDF2 salt and AES nonce per new export. This contains original source findings and therefore requires stronger disclosure controls than the source-free counts-only JSON. The complete encrypted payload is bounded to 3 MiB unencrypted canonical JSON; files bigger than 5 MiB or invalidly shaped packets fail closed.

To reopen with only one file, provide the passphrase and select the .luew. The application decrypts in browser memory, checks the strictly versioned encrypted envelope, all original CSV fields and row limits, re-derives the exact source-byte digest, checks the internal HUMAN journal's digest, row ordering, original finding IDs and allowed HUMAN states, **then asks for explicit replacement confirmation**. A failed decrypt, source mismatch, malformed field or cancelled confirmation preserves all previously loaded workspace state. It does not assert the original exported CSV was genuinely tenant-scoped, authorized or the actual current dataset: that assurance must come separately from the authentic source owner, and a password is not a client signature. No automatic retest, permission or remediation is triggered. Closing the browser drops application state ordinarily; browser memory erasure is not promised.

Browser memory is the only application runtime state; closing the page drops the in-memory session in ordinary operation, and unsaved HUMAN changes request confirmation before navigation. Clear local workspace clears the app-managed state; no browser GC or memory erasure guarantee is made. Downloads and browser history are outside tool control.
