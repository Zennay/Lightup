# LightUp · unified PRIVATE scope operator workroom

**Status: INCUBATE · M3/M7 PLAN/LAB ONLY · DRAFT/HOLD. Not approved for live use.**

This branch composes eight **existing independently owned** scope-authorization companion workrooms into one portable offline package, preserving their exact source bytes. It adds only a navigation hub, offline packaging, unsigned file inventory and operator instructions. It does **not** integrate or promote the original source-owner authorization engine, alter grants, verify client identity, dispatch work, contact a target, modify CI or produce security findings.

## Open and use

1. Open `scope-unified-workspace/index.html` in a local browser, or extract `scope-unified-workspace/LightUp-Scope-Offline-DRAFT-HOLD.zip` first and open its same file. Do not open this bundle from a public web server, email previewer or shared cloud host.
2. Start at **Scope Intake Matrix** and create a HUMAN proposal. Its optional original Casebook import requires the genuine original owner's separately exported PRIVATE file. An arbitrary JSON file is not authenticated source/consent.
3. For an independently obtained original Casebook source history, open **Encrypted Casebook Transfer**, package the original files locally with a new password and convey the resulting packet by a separately trusted channel. Verify the recipient independently.
4. To compare *two human reviewer packages over precisely identical original source bytes*, use **Casebook Reconcile**. Source drift refuses the comparison; conflicts require deliberate HUMAN choices. Never equate a human status with a grant, revocation or finding verification.
5. **Casebook History** is an optional companion **CLI** and documentation, not a fourth ready-made HTML tool. Its original source-owner dependency is held in PR #1620. It is not activated, wired or patched by this bundle.

The start page makes **zero network requests**, uses **zero JavaScript**, contains its own exact-CSP-hash-pinned CSS, and does not write cookies, IndexedDB or localStorage. Each included standalone retains its original implementation, local privacy notices and operating limits. Imported source data and human notes can be confidential; encrypted files and passwords require independent recipient authentication.

## HUMAN teamopvolging en privé overdrachtsbrief

De offline PRIVATE handoff-werkruimte heeft nu zowel een **HUMAN reviewfasefilter** als een **teamfilter**. Teams (Security, Privacy, Client operations, Platform of nog niet toegewezen) krijgen een lokale aantallenindicatie naast de oorspronkelijke brongebonden bestandsrijen. Escalaties blijven zichtbaar als menselijk opvolgwerk, nooit als geverifieerd risico, echte intrekking, voltooiing of toestemming. Zoeken, filteren en teamwijzigingen verlaten het tabblad niet.

**Privacyvriendelijke HUMAN capaciteits-export:** optioneel kan de operator uitsluitend vaste team × reviewfase-tellingen als apart REVIEW_ONLY JSON-document downloaden. Deze nieuwe export bevat geen namen, hashes, bestandsgroottes, routes, broncontent of notities en staat los van de expliciet vertrouwelijke PRIVATE Markdown-brief. Kleine aantallen kunnen in combinatie met externe informatie nog herleidbaar zijn: de UI vraagt expliciete bevestiging en de JSON bevat de waarschuwing en zes onware autoriteitsclaims.

**Direct navigeerbaar HUMAN teamoverzicht:** de PRIVATE offline interface toont per team de aantallen escalaties, nog niet beoordeelde bronverwijzingen, open menselijke onderzoeken en gedocumenteerde (uitdrukkelijk niet opgeloste) vervolgstappen. Via **Bekijk HUMAN dossierlijst** worden de bijbehorende lokale teamrecords zichtbaar; aanwezige tekstzoek- en reviewfasefilters worden daarbij expliciet lokaal teruggezet om verborgen dossiers niet te missen. Het overzicht is enkel een menselijke routeringstabel, geen assessmentoordeel of permissiebron.

**Multi-round HUMAN geschiedenis, uitsluitend historisch en lokaal:** voor de maximaal twaalf meest recente bewust bevestigde bronexacte teampakketretouren bewaart de offline HUMAN-workroom nu een in-memory historisch journaal. Iedere ronde krijgt slechts een eigen **lokale, niet-vertrouwde** volgnummer en een snapshot van de eerder gemaakte PRIVATE ontvangstbon (oorspronkelijke bronverwijzingen plus handmatige oude/nieuwe team/route/fasestatus, geen originele bytes of notitietekst). De operator kan elke historische ronde apart downloaden, alle bewaarde rondes als één PRIVATE JSON bundelen of de volledige lokale historie na expliciete bevestiging wissen. Historische entries blijven als **HISTORISCH / NIET ACTUEEL** gelabeld als de HUMAN werkruimte later wordt bewerkt of een bron wijzigt: ze mogen nooit als nieuwe live scope-, intrekkings- of veiligheidsstatus worden geïnterpreteerd. Het journaal heeft geen automatische opslag en wordt bij verlaten van het tabblad uit de JS-werkset gehaald (geen garantie van fysiek geheugenwissen); al gedownloade vertrouwelijke bestanden worden niet verwijderd. De aparte actuele ontvangstbon blijft per HUMAN-edit direct ongeldig.

**Brongebonden PRIVATE ontvangstbon na echte HUMAN-retour:** na een bewust bevestigde selectieve overname wordt een optionele lokaal te downloaden ontvangstbon beschikbaar. De ongetekende PRIVATE JSON noemt precies de daadwerkelijk aangevinkte originele naam, bytegrootte, ongetekende SHA-256 en structurele bronhint, het oude en nieuwe HUMAN team/route/reviewfase, of er eerder al lokale HUMAN-opvolging bestond, en óf de PRIVATE notitie veranderde. De eigenlijke PRIVATE notitietekst en originele bronbytes worden nooit opgenomen. Het document bevat daarnaast uitsluitend de aantallen uitgezonderde nieuwe, gewijzigde, niet geselecteerde of conflicterende bronnen en literal false authority-flags. Een nieuwe bronselectie, HUMAN-aanpassing of undo/redo maakt de bon ongeldig: hij blijft slechts in dit tabblad beschikbaar zolang de lokale HUMAN toestand niet gewijzigd is. Export vereist een aparte waarschuwing; de bon is geen echte bron-, client-, operator-, revocation-, finding- of release-attestatie en kan privacygevoelige oorspronkelijke bestandsnamen bevatten.

**Conflictbewuste teampakketretour:** per exact ongewijzigde oorspronkelijke bron laat de visuele vergelijking nu ook het lokale HUMAN team en de huidige reviewfase naast de ontvangen HUMAN team/fase zien. Een reeds lokaal beoordeelde bron (fase, team of PRIVATE notitie gewijzigd) wordt standaard **niet** aangevinkt. De operator kiest expliciet per bron welke ontvangen HUMAN-keuzes mogen terugkeren; gewijzigde of ontbrekende oorspronkelijke bronnen zijn nooit aan te vinken. Als de geselecteerde bron al lokale HUMAN-opvolging had, noemt de finale menselijke bevestiging precies hoeveel bestaande lokale beslissingen zullen worden vervangen. Alle overige menselijke keuzes blijven ongewijzigd. Undo/redo, bewaakte revisies en bronexactheid blijven behouden. Een teampakket is privé metadata, niet geauthenticeerd en mag geen echte scope, grant of intrekking bewijzen.

**Bronexacte selectieve HUMAN voortzetting:** naast strikt heropenen van de hele identieke bronselectie kan een eerder PRIVATE `lightup.scope_handoff_PRIVATE_inventory.v1` reviewplan nu *selectief* worden meegenomen naar een bewust nieuw samengestelde verzameling originele bronnen. Het originele begrensde parsercontract, alle onware autoriteitsflags en duplicate-keyweigering blijven intact. Per huidige bron vergelijkt de app de letterlijke originele bestandsnaam, bytegrootte, SHA-256 en originele structurele type-hint; alleen bij volledige gelijkheid stelt de app menselijke fase/team/route/PRIVATE-notitie voor. Gewijzigde bronnen, nieuwe bronnen en uit de selectie afwezige bronnen krijgen nooit oude statussen; afwezigheid is nadrukkelijk geen intrekking, oplossing of veiligheidsresultaat. De app maakt eerst een aparte PRIVATE visuele bronregel-preview met EXACT / CHANGED / NEW / ABSENT en aantallen, zonder te wijzigen. Alleen een aparte daarna vrijgegeven knop met expliciete menselijke bevestiging mag de bronexacte HUMAN-keuzes toepassen. Elke tussentijdse HUMAN-bewerking, undo/redo of bronselectiewijziging maakt die tijdelijke preview direct ongeldig. De app toont aantallen *voordat* de gebruiker een expliciete herstelbevestiging kan geven. Lopende bron- of HUMAN-edits breken de import geheel af; ongeldige invoer laat de huidige werkruimte onaangeroerd. Een geslaagde selectieve menselijke statusovername kan met de bestaande undo-functie worden teruggedraaid. Originele bronbytes, toestemming, grants, gebruikersidentiteit, scanners of backend worden niet gelezen of gewijzigd.

**PRIVATE notitieteksten standaard niet verspreiden:** voor de eigen team-MD en brongebonden JSON is er nu één afzonderlijk aan te vinken optie om expliciet PRIVATE HUMAN notitieteksten op te nemen; standaard staat deze UIT. Het team-JSON gebruikt voor de nieuwe export een streng schema `lightup.scope_handoff_PRIVATE_inventory.v2`, inclusief per bron een verplicht exact boolean `private_note_included`. Als dit false is, MOET de meegestuurde `private_human_note` leeg zijn; import weigert het hele pakket anders. Bij selectieve én strikt bronexacte herimport behoudt de ontvanger zijn reeds lokale notitie als geen notitie is meegestuurd, in plaats van die stilzwijgend te wissen. Bestaande oorspronkelijke v1 PRIVATE inventarissen blijven volledig leesbaar en betekenen expliciet dat het notitieveld wél is aangeleverd (ook als het leeg is). De PRIVATE ontvangstbon zegt daarom afzonderlijk of een notitie daadwerkelijk is overgedragen en markeert een notitie als gewijzigd uitsluitend als die informatie aanwezig is. Het pakket blijft ongetekend, niet-geauthenticeerd en nooit een bron van echte toestemming of grant.

**Structureel bronexact PRIVÉ HUMAN-teampakket:** selecteer één *toegewezen* menselijk ontvangend team. Naast de minimum-MD-brief kan de operator nu een lokale PRIVATE JSON exporteren met uitsluitend de oorspronkelijke bronverwijzingen die echt voor dat team zijn geselecteerd. Het teampakket gebruikt exact de bestaande streng begrensde `lightup.scope_handoff_PRIVATE_inventory.v1` entry-structuur, met originele naam, bytegrootte, ongetekende SHA-256, originele structurele hint en de vier HUMAN velden. Daardoor kan de ontvanger eerst de originele bestanden onafhankelijk lokaal selecteren en later via de bestaande **bronexacte selectieve HUMAN import** antwoorden terugbrengen. Andere teams, oorspronkelijke bronbytes, privébestanden en overige reviewnotities worden niet meegenomen. Bronhash is géén bronauthenticatie; passende onafhankelijke ontvangerverificatie en bescherming van deze vertrouwelijke JSON blijven noodzakelijk. Het team `unassigned` mag geen extern teampakket maken; ontbrekende/gewijzigde bron blijft een nieuwe HUMAN-reviewsituatie, nooit een grant, consent of intrekking.

**Minimaal noodzakelijke PRIVATE teamoverdracht:** kies expliciet precies één voorgesteld HUMAN team en download de nieuwe **PRIVATE minimum noodzakelijke teamoverdracht (.md)**. De brief bevat alleen de oorspronkelijk geselecteerde, voor dat team gemarkeerde bronverwijzingen, geordend naar HUMAN fase. Ook als de tabel op een andere reviewfase is gefilterd, worden uitsluitend maar *alle* dossiers van het gekozen team opgenomen; er worden nooit bronverwijzingen of werkdrukcijfers van andere teams gelekt. Er wordt geen oorspronkelijke filecontent meegestuurd, alleen bronmetadata en eventueel vertrouwelijke HUMAN-notities van dat team. De ontvanger is niet geauthenticeerd: bevestig echt ontvangerschap, privacybeleid en beschermd kanaal buiten deze app. Kies geen team zonder een bestaande expliciete HUMAN indeling. Volledige privébrieven en bronvrije aantallen blijven afzonderlijke handmatig bevestigde functies. Geen evidence-validatie, klant-/operatorconsent, grant, scan, intrekking of deployment wordt geraakt.

**HUMAN undo/redo, uitsluitend voor de lopende review:** voor de laatste maximaal 32 lokale acties kan de operator route, individuele HUMAN-fase, teamkeuze, PRIVATE notitie (per typbewerking/focus) en de bevestigde bulk-/bronexacte HUMAN-heropenactie terugdraaien en opnieuw uitvoeren. Elke wijziging aan de originele bronselectie (toevoegen, verwijderen of wissen) gooit de geschiedenis bewust weg; herstel haalt nooit verwijderde bronfilehandles terug en is geen fysiek geheugenwisbewijs. De geschiedenis blijft uitsluitend lokaal in het tabblad en wordt niet geëxporteerd. Tijdens een asynchrone heropenactie wordt nu óók een interne HUMAN edit-revisie bewaakt, zodat een lokale team-, fase-, route-, notitie- of bulkbewerking niet stilzwijgend door een net gelezen PRIVATE reviewplan wordt overschreven. De bronidentiteit en eigen bestandsordening blijven onafhankelijk verplicht. Geen grants, clientidentiteiten, I/O-gates, bronnen of werkelijke autorisatie wijzigen.

**Gerichte bulkroutering:** stel eerst de filters op HUMAN reviewfase, team en/of een exacte lokale bestandsnaamzoekterm in. Kies vervolgens voor maximaal de nu zichtbare dossiers een nieuw HUMAN team en/of een nieuwe HUMAN reviewfase. De app toont vóór de wijziging het precieze aantal in een menselijke bevestiging; zonder bevestiging wijzigt niets. De originele bronbytes blijven onveranderd. Een wijziging kan dossiers uit de actieve filterweergave laten verdwijnen. Bulkstatussen zijn nooit security-/consent-/revocation-besluiten en beïnvloeden de oorspronkelijke LightUp-autoriteit niet. De private brief blijft bewust een volledige overdracht van de volledige huidige selectie, niet slechts het filterresultaat.

Via **PRIVATE HUMAN team- en escalatiebrief (.md)** kan een gebruiker, na een aparte waarschuwing en bevestiging, een lokaal Markdown-overdrachtsdocument maken. Het groepeert *alle* bewust geselecteerde bestanden per team en binnen het team per HUMAN reviewfase, met originele bestandsnamen, bytes, ongetekende SHA-256, structurele bronhints, handmatig gekozen route en PRIVATE notities. Filters in de interface beperken de export niet stilzwijgend. De originele inhoud wordt niet in het document opgenomen of gewijzigd. Menselijke notities en bestandsnamen kunnen vertrouwelijk zijn: deel alleen via een apart geauthenticeerd passend privé-kanaal. De brief is ongetekend en bevat expliciete letterlijke authority=false aanduidingen en een verplichte echt-bron/consent/revocation/HUMAN GO-waarschuwing; een briefing is **geen** Security PASS, toestemming of testbewijs.

## Structural source routing without authenticating consent

The private handoff workroom includes its own **new source-inspector.js**, stitched into the existing CSP-pinned standalone. It rejects duplicate JSON keys, invalid UTF-8, oversized/unbounded JSON, and malformed declared original Studio DRAFT_ONLY, Casebook REVIEW_ONLY and operator-readiness REVIEW_ONLY source envelopes; unknown JSON remains **unverified/manual** and no arbitrary bytes become trusted. It shows category and non-sensitive source totals only, never injected inner HTML, original tenant IDs, client labels or asset hostnames. JSON imported through this companion still requires full independent re-validation by the *original receiving workroom*. This is not equivalent to source authentication or operator consent.

## Pin every imported original to its copied source bytes

The committed `PINNED-ORIGINALS.json` enumerates **all 60 copied original files** under eight owner compartments, with exact declared original PR HEAD, original relative path, byte size and SHA-256. `source_pins.py` is a fail-closed local **product build prerequisite**, not a QA suite: `build.py` refuses to package an added, removed, renamed, symlinked, size-changed or byte-changed original file, and rejects an unrecognized/mismatched source-head claim. To refresh originals deliberately, separately re-verify the exact upstream PR head, record all changed files and update the pin document in a dedicated reviewed composition commit. Never silently edit a copied original's code.

The committed SHA-256 inventory is **unsigned**: it detects accidental drift relative to this Git commit, but does not independently authenticate GitHub, the original developer, client/tenant identity, consent or release. Exact SHA content review, original source-owner approval and mandatory original hosted and named VPS CI still remain outside this offline bundle.

## PRIVATE multi-workroom handoff shelf

Open `scope-unified-workspace/handoff.html` on a trusted offline browser. Import up to 16 local files (max 8 MiB/file, 32 MiB total), calculate SHA-256 in memory, choose a destination workroom and optionally download the unchanged original bytes. Known JSON route suggestions use bounded content-level format inspection with duplicate-key rejection, but are never producer, tenant or consent verification. Encrypted inputs stay opaque. The destination app receives no automatic transfer: the HUMAN operator must explicitly select the original file again in that app. No network, cookies or persistent browser storage.

Any collision of normalized (NFC/case-insensitive) original filenames now HOLDs the **whole** incoming batch, even when different bytes claim the same name; manually remove a prior version before introducing its replacement, so a case never silently switches between source revisions.

The workroom now has PRIVATE in-tab **local text search and HUMAN-stage filtering** for navigating the source-bound review desk; filters affect presentation only, never file admission, origin binding or the complete source inventory export.

Each selected original file now gets source-SHA-256-bound **local HUMAN triage**: unreviewed / preparing / escalated / documented-but-NOT-resolved, a team (security, privacy, client operations, platform or unassigned), and an optional 280-character PRIVATE note. These HUMAN values do not change the original source, signal real consent or revoke grants. Removing the original also removes its local HUMAN choices.

Two separately confirmed exports are available: an anonymous route-counts JSON without source identifiers; and a PRIVATE original filename+size+unsigned-digest+HUMAN stage/team/private note handoff containing potentially sensitive details, to be transferred only to authenticated recipients. Browser memory wiping is not guaranteed. No grants, dispatch or revocation are performed.

The integrated handoff screen now provides **read-only previous-vs-current source comparison**. ## Browser-only package digest (no Python required)

Open **scope-unified-workspace/verify.html** locally, select the received ZIP, and optionally paste its expected SHA-256 from a **separately authenticated, independent source**. The browser calculates SHA-256 with Web Crypto in memory, never uploads any bytes, and never saves data. A digest match is **REVIEW_ONLY**, not the original source, consent or authorization proof. For an actual per-file inventory check use the separate offline Python checker below. The browser falls back to a HOLD notice when Web Crypto is unavailable.

## Inspect a received package without extracting it

On a trusted local machine with Python 3, the independent non-authorizing read-only tool checks the complete ZIP or a **freshly extracted** bundle against its unsigned inventory and exact pinned source-head declarations:

    python3 scope-unified-workspace/check_bundle.py --zip scope-unified-workspace/LightUp-Scope-Offline-DRAFT-HOLD.zip

    python3 scope-unified-workspace/check_bundle.py --directory /path/to/newly-extracted-bundle-root

Successful byte-level transport comparison explicitly returns **REVIEW_ONLY (exit 3)**, never authorization or exit 0. Malformed, incomplete, modified, unexpected, symlinked or unbounded input yields **HOLD (exit 2)**. This cannot authenticate the source: the inventory is unsigned, so an adversary could change both package bytes and manifest. Treat any received package as untrusted until original channel/source and intended recipients are independently verified. This CLI does not extract files, run scripts from the archive, contact anything or read client data.
